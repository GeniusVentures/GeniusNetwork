# Stack Research — v1.2 SuperGenius Cold-Storage Archive Integration (workstream rocksdb-backup)

**Domain:** Tiered-node archive semantics (archive/cold vs light/pruned) layered onto the validated v1.0/v1.1 cold-storage stack
**Researched:** 2026-11-13
**Confidence:** HIGH for all in-tree claims (every capability verified against workspace source; paths cited). MEDIUM for upstream-s3d lifecycle claims (verified on s3d master/v0.3.0 README; **unverified at our pinned v0.2.1** — and not needed). HIGH for BIP-159 (official BIPs repo) and RocksDB manual-compaction semantics (official wiki, cross-checked against the in-tree 9.4.0 headers, which are authoritative for our pin).

**Bottom line:** **Zero new libraries.** Every NEW v1.2 feature — durability-gated TxPruner eligibility, archive serving from cold, TxPruner×GC composition, cold-tier collectibility policy, seal growth, and the bootstrap-branch merge — is satisfiable by composing capabilities that already exist in the pinned stack (RocksDB 9.4.0, vendored ipfs-lite-cpp graphsync + extensions, libp2p fork identify, minio-cpp 1.0.0 / s3d v0.2.1 admin facade, protobuf 7.34.0). The work is contract/protocol-shape and policy decisions at existing seams, not dependency decisions. The develop-side v1.2 research conclusion ("RocksDB 9.4 + vendored ipfs-lite-cpp already provide the full API surface — no new storage dependencies") extends unchanged to the archive-tier features.

### Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|----------|-------------|-------------|---------|
| Hot reclamation | `CompactRange(kForce)` post-erase | RocksDB `DeleteRange`-based pruning | PRUNE-02 already standardizes point-deletes in one atomic WriteBatch; range tombstones bring hidden-snapshot interaction complexity and no reclamation win (bottommost compaction is still required). Also explicitly rejected by develop-side v1.2 scoping |
| Hot reclamation | manual `CompactRange` off the hot path | Compaction filter framework (`kIfHaveCompactionFilter`-driven GC) | A filter that could drop keys autonomously is exactly the "silent deletion" class the design refuses; erase decisions are evidence-driven (WriteBatch), compaction is only the janitor. Out-of-scope discipline from v1.2 develop carries over |
| Pruned-vs-archive signaling | protocol-string advertisement + graphsync extensions | New peer-discovery/routing service, or bitswap 1.2.0 DONT_HAVE upgrade | Graphsync is the serving path (`GraphsyncDAGSyncer`); extensions + response codes cover the same ground in-protocol; a discovery service is a new moving part with no consumer yet |
| Serving old data from cold | refine existing re-warm (`ColdServeDagService` + `EnqueueRewarm` retry ladder) | Synchronous blocking cold reads in the responder | v1.1 SC2 hard-won invariant: never block the pubsub host's single thread — a wait there freezes the node. Keep the async re-warm ladder; v1.2 only refines *which* negative/positive code completes the first attempt and what the forced walk restores |
| Cold collectibility | node-local policy + explicit `S3Client::Delete` if ever enabled | s3d/S3 bucket lifecycle rules | Time/prefix-based rules can't see node-local prune evidence; layout isn't policy-scoped; surface unverified at pinned v0.2.1. Revisit only with a real downgrade-with-collection product requirement |
| "Permanent once written" enforcement | documented app-level policy | s3d Object Lock COMPLIANCE (upstream) | One-way and bucket-wide in effect; interacts with versioning and create-only conditional PUTs; enforces a policy v1.2 hasn't decided to need. Document as a future option for archive nodes wanting server-side irreversibility — requires s3d bump first |
| Seal capacity | measure + accept + document | Column-family rework / seal spill through BlockStore | Seals aren't DAG blocks (note: "blockstore spill doesn't apply naturally"); CF rework was explicitly out-of-scope on develop v1.2 and vendored-change discipline (`removeSeal` ban) is the same boundary. RTN-02 already tracks lifecycle — don't solve an unmeasured problem |

## Integration Points

Where each NEW feature lands on existing seams (the roadmapper's phase hooks):

1. **Durability gate → eligibility** (`SuperGenius/src/transaction/PruneEligibility.*`, `TxPruner.*`): the eligibility evaluator gains a cold-durability precondition consulted through the v1.1 gate vocabulary — `ColdStorageManager::GetUploadState` (`ColdStorageManager.cpp:727`) against `kEvictionDurabilityGate` (`ColdStorageManager.hpp:136`). "Never erase what isn't in cold" = erase allowed only when the block's upload state clears the eviction gate (Durable + Unreadable shape). Role widening: GATE-01's `NodeType::Light`-only fail-closed check (`PruneEligibility.cpp:129`, `TxPruner.cpp:72`) becomes a policy matrix (Light = unconditional local pruning; Full-with-cold = durability-gated; Full-without-cold = never) driven by a `sgns_config.json` knob beside `node_type` (GATE-06 resolution/logging discipline).

2. **Archive serving** (`SuperGenius/src/crdt/impl/graphsync_dagsyncer.cpp:108–134` + `globaldb/BlockStoreBackedIpfsDatastore.cpp:126`): `ColdServeDagService::getNode` is the single decision point. v1.2 refines the negative-completion policy by consulting local prune evidence before/alongside `EnqueueRewarm`: GC-evicted + cold-resident + no prune evidence → this node IS the archive → re-warm serve path (existing ladder); TxPruner-erased + `/prune/tx/` marker present → refuse as history-pruned (distinct from don't-have). Refusal still rides existing `ResponseStatusCode` values (SURV-02 already maps "history pruned" ≠ not-found locally; the wire-level distinction goes in a graphsync **extension** entry, not a new status code).

3. **Graphsync extensions plumbing** (`thirdparty/ipfs-lite-cpp/.../marshalling/` + `impl/extension.cpp`): define one extension name (e.g. `graphsync/extension/sgns-prune-evidence`) carrying the refusal reason. Builders/parsers already handle arbitrary extensions end-to-end; the metadata extension (`encodeMetadataRequest`/`encodeResponseMetadata`) is the in-tree template.

4. **Role advertisement** (`impl/network/network.cpp:36` + `thirdparty/libp2p/src/protocol/identify/`): register the archive-role protocol string in the existing handler list; identify then advertises it via `getSupportedProtocols` (`identify_msg_processor.cpp:53`). BIP-159 discipline adopted verbatim: pruned nodes never advertise the full-serving signal (v1.2 develop out-of-scope already encodes "pruned must not masquerade"); don't leak prune depth (serve/refuse uniformly at the threshold, no depth-probing oracle).

5. **TxPruner × GC composition** (`GlobalDB::EraseEntry` at `globaldb.cpp:1374–1451`, `GraphsyncDAGSyncer::StageBlockRemoval` at `impl/graphsync_dagsyncer.cpp:620`, GC's `DeleteCIDBlock` + disposed markers): both pruners converge on the same one-block-key home; unify or explicitly sequence their hot-cleanup passes. Seals are never deleted by either (GATE-03, keep-seal commit `7961ec264`).

6. **Reclamation on dual-instance setups** (hot: vendored `RocksdbDatastore`; cold-local: `sgns-blockstore/LocalBlockStore.cpp:367–415` with 4 CFs): `CompactRange(kForce)` runs on the **hot** instance only (it is where TxPruner/GC deletes happen; the cold-local instance is append-mostly and needs no forced compaction this milestone). The two DBs share nothing at the RocksDB level (separate LOCK/MANIFEST/WAL) — the real interactions are operational: (a) a full-range kForce compaction temporarily needs roughly the compacted live-set's space in new SSTs while old ones persist — budget this on volumes shared with cold staging and s3d's disk buffer (`sia.diskUsageLimit`, default 10 GiB staging upstream); (b) IO contention with the drainer/re-warm executor — keep scheduling off the hot path (RECL-01's stance) and keep `exclusive_manual_compaction = false` (the 9.4 default per in-tree `options.h`; the official wiki's "default true" text is stale — trust the header) so spill writes are never fenced out; (c) `canceled` atomic wired to shutdown; (d) seal keys (`<cid>sealed`, string keys) share the hot default CF adjacent to binary CID keys — range-bounded tx-prefix compactions won't disturb them, full-range compactions merely repack them (they never tombstone), and with no compaction filter installed nothing can ever drop them.

7. **Collectibility policy** (if enabled): an evidence-driven collector above `sgns-blockstore` using the installed `S3Client` SPI's `Delete` — mirroring how `ColdStorageManager` consumes `S3AdminClient` (library interface installed, impl private). The frozen v1 BlockStore contract stays delete-free; role downgrade is a documented policy state machine (archive → draining → collectible-eligible), with cold-object deletion only ever behind local evidence, never a bucket-wide rule.

8. **Seal capacity**: measurement probe against `RocksdbDatastore::seal` growth (O(all processed CIDs), ~60–70-byte keys + empty values, now also the forced-walk ancestry index post-merge); report in the existing GC/retention observability log (RECL-03 shape). Decision gate for any future spill surface — not this milestone.

9. **Bootstrap-branch merge**: `fix/trust-genesis-bootstrap` lands on `dev_coldstorage_additions` as a git merge (forecast: only `GeniusNode.cpp` conflicts; CRDT seams auto-merge). Composition is verification work, not build work: forced-walk `retained ? GetStoredNode : getNode` meets the Phase-9 cold-read seam; `CanRestoreElement` is the pruned-vs-evicted pivot (local evidence decides; cold bytes are never authoritative on their own).

## What NOT to Add

| Do NOT add | Why | Use instead |
|------------|-----|-------------|
| Any new thirdparty library | Every v1.2 capability is covered by pinned in-tree mechanisms (table above) | Existing seams listed under Integration Points |
| RocksDB upgrade (9.5+/10.x) | Full API surface for kForce manual compaction, subcompactions, cancellation already in 9.4.0 headers; an engine bump invalidates v1.0/v1.1 evidence for zero feature gain | Stay pinned 9.4.0 |
| Compaction-filter-based deletion | Autonomous key-dropping during compaction bypasses the evidence-driven WriteBatch discipline; also opens the "silent deletion" hazard class the design explicitly refuses | Point-deletes (PRUNE-02) + janitor compaction (RECL-01) |
| `DeleteRange` for pruning | No reclamation benefit without bottommost compaction anyway; range-tombstone semantics add crash-consistency and snapshot-interaction surface PRUNE-04 doesn't need | Existing atomic one-batch point deletes |
| s3d version bump for lifecycle/Object Lock | Lifecycle surface unverified at pinned v0.2.1; rules can't express evidence-driven per-CID collection; Object Lock is one-way and premature | App-level policy + `S3Client::Delete` (only if collectibility is ever permitted) |
| S3 bucket lifecycle rules (even on MinIO where minio-cpp supports them) | Time-based/prefix-based expiry contradicts evidence-driven, node-local collectibility; layout isn't policy-scoped | Node-local evidence + explicit deletes |
| New peer-role discovery/routing service, IPNI indexer, bitswap DONT_HAVE upgrade | Graphsync extensions + response codes + identify protocol-list already cover pruned-vs-archive signaling with zero new moving parts | Extension name + second advertised protocol string |
| Bitswap/graphsync protocol fork changes | The vendored graphsync already carries extensions end-to-end and a multi-protocol handler registration; no fork edit required for signaling | Configure/extend, don't fork |
| Vendored ipfs-lite-cpp changes (seal CF rework, `removeSeal`, seal spill into BlockStore) | Seals aren't DAG blocks; CF rework and vendored edits are the v1.2 develop out-of-scope boundary and GATE-03 territory | Measure + document (RTN-02 tracking) |
| New column families on the hot DB | Not needed: no filter-based GC, seals must survive compactions anyway (they always do — no filter, no delete) | None |
| CARv2 export / snapshot tooling, metrics surface, watermark auto-GC | Still on the deferred list from v1.0/v1.1 — unchanged, not triggered by archive semantics | Defer (STATE.md Deferred Items) |
| New test framework or e2e harness | Three-tier strategy + Tier-1 fail-closed lane is the validated spine | New GTest/CTest cases under existing labels |
