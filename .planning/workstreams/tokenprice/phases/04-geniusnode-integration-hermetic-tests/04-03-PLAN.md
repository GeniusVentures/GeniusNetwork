<objective>
Rewrite `price_retrieval_test` from a deliberately-unregistered live CoinGecko smoke suite into a hermetic, CTest-registered integration suite (TEST-05, D-10/D-11/D-13): one `HttpStubServer` serves BOTH tiers via distinct scripted paths (`/api/v3/simple/price` CoinGecko shape, `/v1/prices` Phase 1 envelope shape), env vars redirect both tiers to it before `GeniusNode::New`, and the scenarios drive the real wired seam `GeniusNode::GetCoinprice` — proving env-redirect → lazy manager → node seam → fallback tiers end-to-end with zero live network. Historical-endpoint tests are deleted with the retriever (D-09); the three live tests' current-price case maps to the new happy path.

Purpose: TEST-05 — no live CoinGecko calls anywhere in the suite — and D-13's end-to-end proof of the milestone Core Value (price-dependent paths never hard-fail when CoinGecko is WAF/limit-blocked) through the node seam, beyond what `price_manager_test` proves with fakes.

**Open-question resolutions locked by this plan:**
- **O2 (fixture weight / TEST_F list):** full-`GeniusNode` integration — the honest reading of D-10 ("drives the real wired path"). Accept the heavyweight link (`genius_node_test` + `json_secure_storage` + `price_test_support`, account-suite shape) and the account fixture's proven node bootstrap. TEST_F list (5): happy path / tier-1-403 → tier-2 envelope fallback / warm-then-fail fresh-L1 / 429 handling / empty-ids seam contract.
- **O3 (LKG-through-seam scope):** NOT included. A true >60s-stale LKG cannot be driven through the node seam (the manager's real clock is not reachable; sleeping 61s in a test is unacceptable). LKG stays proven in `price_manager_test` with its injectable clock; D-13's warm-then-fail is satisfied here by fresh-L1 + tier-2 fallback. No clock-injection seam is added to production for this.
- **A4 consequence:** the warm-then-fail scenario's post-flip service comes from the fresh L1 (within the 60s window) or tier 2 — that is the honest seam-level proof.

Scope guard: this plan touches ONLY the price_retrieval suite — the account suite is 04-02. Both consume 04-01's `ScopedEnvVar` + cutover and are parallelizable.
