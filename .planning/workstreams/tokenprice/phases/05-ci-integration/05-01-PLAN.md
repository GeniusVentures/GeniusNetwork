| Boundary | Description |
|----------|-------------|
| GitHub event and changed paths → Worker job | Repository-root-relative pull-request and push paths select whether the Worker toolchain runs. |
| GitHub Actions runner → npm registry / Worker scripts | CI installs the Worker project's pinned dependencies and executes repository code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Changed-file gate and Worker job | mitigate | Scope the filter to `pricecoordinator/**` relative to the SuperGenius repository root; default to running only for a positive match or explicit manual dispatch; give the job read-only `contents` and `pull-requests` permissions and no deployment secrets. |
| T-05-02 | Elevation of Privilege | Actions runner token | mitigate | Restrict the new job to `contents: read` and `pull-requests: read`; do not grant package-write, contents-write, or deployment permissions. |
| T-05-SC | Tampering | npm / GitHub Actions dependencies | mitigate | Add no package dependencies; use the audited, committed Worker lockfile with `npm ci`, and follow the workflow's established Actions version conventions. No `[ASSUMED]` or `[SUS]` npm package is introduced, so no legitimacy checkpoint is needed. |
</threat_model>
