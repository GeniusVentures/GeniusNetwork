## SCHEMA AMENDMENT — stop-string job-JSON carriage (escalated, NOT Phase 3 scope)

The Phase 1 `gnus-processing-schema.json` `ElmGeneration` object has exactly four generation fields — `max_output_tokens`, `temperature`, `top_p`, `seed` — and NO `stop` field (verified against the shipped schema). Carriage from requestor JSON (a `stop` array on `ElmGeneration`) requires a Phase 1 schema amendment + quicktype regeneration + validator update. That amendment is **Phase 4's** to carry (it owns the splitter/submit wiring that would consume the field). Do NOT amend the schema in Phase 3.
