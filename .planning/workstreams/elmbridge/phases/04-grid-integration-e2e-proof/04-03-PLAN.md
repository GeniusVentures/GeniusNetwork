<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| requestor job JSON → splitter/submit | elms[] and the funding block cross from the requestor into grid state and escrow |
| submit → CRDT/escrow ledger | the rate record and escrow info must be atomic (crash-or-nothing) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | elm_subtask_map injection via job JSON | mitigate | The splitter OVERWRITES taskJsonRoot["elm_subtask_map"] unconditionally at split time (requestor-supplied maps never survive); readers resolve via the splitter-written task JSON only |
| T-04-03-02 | DoS | huge elms[] arrays | accept | Phase 1 gates bound the job (uniqueness, charset); subtask count equals elms count — same order as a chunked job of N chunks; no new amplification |
| T-04-03-03 | Tampering | split CRDT transaction (rate record orphaned) | mitigate | P4-9 composition: elm_rate Put rides the escrow-info transaction; EnqueueTask commits once — a crash between hold and enqueue leaves the standard HoldEscrow recovery path, no orphan |
| T-04-03-04 | Elevation | ELM branch reaching the chunk splitter | mitigate | The two branches are mutually exclusive on the job_type sniff; the chunk loop is unreachable for elm_processing (and vice versa the ELM loop for legacy) |
| T-04-03-SC | Tampering | package installs | accept | No new packages (D-003) |
</threat_model>
