<objective>
Surface `required_memory_bytes` from the manifest runtime block into the existing CapabilityValidator as a local preflight: add a host-RAM axis to the capability snapshot (open question A3 resolved — option (ii), host-RAM query, because the field exists precisely to prevent loading a model the machine cannot hold, and the GPU-heap-only alternative is wrong for CPU-backend models), implement `CheckElmResources` as a new plain-values entry point (CanExecute is pass-shaped and stays untouched), and lock it with mock-snapshot tests using the established `SGPROCMGR_TEST_FRIEND` / `SetSnapshotForTest` injection pattern.

Purpose: ELM-13/Pitfall 13 — a node must refuse an ELM job whose model cannot fit before downloading hundreds of megabytes. The check is local-only (no capability advertising — binding Out of Scope); the call site lands in Phase 3's processor integration, but the validator half ships now so P3 only wires it.
Output: extended snapshot + `CheckElmResources` + `sgproccapability_elm_resources_test` green, committed in the SGProcessingManager repo.
</objective>
