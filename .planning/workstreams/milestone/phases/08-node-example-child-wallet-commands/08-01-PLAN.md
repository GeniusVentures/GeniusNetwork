<objective>
Add three interactive REPL commands to `node_example` — `childbalance`, `listchildren`, and `registerchild` — each a thin wrapper over an existing, already-tested `sgns::GeniusNode` C++ method (`GetChildBalance`, `GetRegistrationsForMain`, `RegisterChild`). No new proto, consensus, GeniusNode/GeniusSDK API, or CMake target work — only additions inside `SuperGenius/example/node_test/NodeExample.cpp`.

Purpose: Lets an operator register the running `node_example` instance as a child wallet, discover all children registered to a main wallet (with balances), and query any child's balance — entirely from the existing interactive console, per NEXC-01/NEXC-02/NEXC-03.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Operator keyboard -> REPL command dispatch | `process_events`/`split_string` parse raw stdin text into `args`, then dispatch to `cmd_*` handlers with no framework-level sanitization |
| `cmd_childbalance` token_id argument -> `sgns::TokenID` | Untrusted hex string parsed via `parse_token_id`/`boost::algorithm::unhex` into a fixed 32-byte buffer |
| `cmd_registerchild`/`cmd_listchildren` main_address argument -> `GeniusNode`/`TransactionManager`/CRDT layer | Untrusted address string passed through unmodified; format/consensus-level validation happens downstream (already covered by Phase 5's `FilterRegistration`/`RegistrationTransaction` tests) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `parse_token_id` (childbalance token_id argument) | medium | mitigate | Reject any input that is not exactly 64 hex digits (after optional `0x`/`0X` strip) and any input that throws during `boost::algorithm::unhex`; log an error and abort before calling `GetChildBalance` — never pass unvalidated bytes into `TokenID::FromBytes` |
| T-08-02 | Denial of Service | `cmd_registerchild`/`cmd_listchildren` main_address argument (unvalidated format/length) | low | accept | `node_example` is a local operator console passing the raw CLI arg straight through; format/length/consensus validation is already enforced downstream in `TransactionManager`/`FilterRegistration` (Phase 5, existing and tested) — an invalid address simply returns a logged `outcome::result` failure, no unsafe memory access in this file |
| T-08-03 | Information Disclosure | `childbalance`/`listchildren` printing child balances and addresses to local stdout | low | accept | `node_example` is a local interactive operator tool (no remote log shipping); consistent with the existing `info`/`balance`/`ds` commands that already print account balance/address/datastore contents locally |
</threat_model>
