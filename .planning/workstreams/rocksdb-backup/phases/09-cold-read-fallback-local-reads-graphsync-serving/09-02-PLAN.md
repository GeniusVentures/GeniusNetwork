<objective>
Deliver READ-02: graphsync serving for a CID not held locally performs an async cold fetch on a bounded dedicated executor with a deadline, off the responder's inline path, CID-verifies, then serves — implemented in the locked D-05 shape: immediate honest don't-have + coalesced background re-warm (D-05/D-06/D-07), with the measured cold-serve latency budget documented as the built-in default per D-12.

Why this shape (binding, 09-RESEARCH §1/§5/§6): the responder runs on the pubsub host's SINGLE-THREADED io_context (gossip_pubsub.cpp:518, globaldb.cpp:637-643); any wait in the serve path freezes all pubsub + graphsync stream processing. The responder can only send RS_FULL_CONTENT or RS_NOT_FOUND synchronously inside the posted task (graphsync_impl.cpp:396-446); late/cross-thread responses require rejected thirdparty surgery. Therefore the deadline-expiry negative completion IS the immediate don't-have, and the deadline governs the background re-warm — a hold-to-deadline responder is NOT implementable and D-05 is the only honest shape. Requester-side safety is verified: RS_NOT_FOUND writes no peer blacklist (IsConnectionFailureStatus covers only connection statuses, graphsync_dagsyncer.cpp:1136-1146), only a 4 s per-(peer,cid) suppression, and the 5 s→60 s failed-root retry ladder finds the re-warmed block hot.

Purpose: peers can obtain cold CIDs from this node without the node ever freezing; the SC2 evidence bar (responder-freeze regression, latency budget) is measured hermetically.
Output: ColdReadService re-warm executor + ColdServeDagService wrapper + lifecycle bridges + cold_read_freeze_latency_test (SC2 benchmark + freeze regression).
</objective>
