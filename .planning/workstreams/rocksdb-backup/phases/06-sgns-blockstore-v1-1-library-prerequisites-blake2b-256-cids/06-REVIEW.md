## Review-focus cross-check

1. **Hash-verification integrity (no bypass path).** All six verify sites (Put+Get × Local/Memory/S3) now recompute with the CID's own multihash — grep confirms exactly 6 `cid.content_address.getType())` call sites. Gate coverage enumerated at HEAD: Local 8 call sites (Put 300, Get 406, Has 483, GetSize 509, PutMany pre-pass 542, TransitionJournal 663 — covering `MarkUploadedAccepted`/`MarkUploadedDurable` which delegate — GetUploadState 704, EvictLocal 736), Memory 5 (Put 66, Get 98, Has 135, GetSize 145, PutMany 167), S3 5 (Put 126, Get 172, Has 212, GetSize 228, PutMany 258). `GetPendingUploads`/`ForEach` take no CID argument (iterate gate-passed stored keys). **No bypass path exists.**
2. **Throw contract.** Every gate is the first statement of its op — before any RocksDB access, memory mutation, or S3 adapter call/key derivation; `CidOf`'s `default:` throws before any hashing; PutMany validates the whole batch before any write on all three backends (mid-batch throw cannot leave partial writes). Contract is throw-for-programmer-error / result-for-runtime-failure consistently, documented in `Cid.hpp:88-92` and `S3Client.hpp:197-206`, and pinned by `ThreeArgUnsupportedHashThrows` (sha512 + blake2s128), the kit's `PutRejectedHash/GetRejectedHash/PutManyRejectedHashThrowsBeforeAnyWrite` macros, per-backend sha-512 suites, and the journal-tooling probes in `TransitionsRespectEntryGates`.
3. **Pinned literals.** Spot-checked all three CID literals against `docs/evidence/blake2b-crosscheck/getcidof-crosscheck.log`: `a0`→`bafy2bzacedjwujq...kcwwy`, `a1636b657901`→`bafy2bzacebonb5h...msdq`, `a16568656c6c6f...`→`bafy2bzacedtxqx7...3av4` — byte-identical in `cid_spike_test.cpp` (`Blake2bDagCborKnownVector`), the kit's `pinned_cids[0..2]`, and the S3 key-layout literal `v1/blocks/dag-cbor/d3/bafy2bzacedjwujq...kcwwy`, whose fan-out byte `d3` is the first byte of the logged independent digest `d36a2619...` (Python hashlib, two-source D-02 discipline). The `dag-cbor` key token traces to `CodecToken(DAG_CBOR)` at `S3BlockStore.cpp:57`. All trace cleanly.
4. **The factory (`OpenMinioS3Client`).** Eager validation throws `std::invalid_argument` on empty endpoint/bucket before `Impl` construction (`MinioS3Client.cpp:140-145`); construction builds BaseUrl/StaticProvider/Client locally with zero network I/O, proven in-tree AND at the consumer boundary against the non-listening `127.0.0.1:1`; no logging anywhere on the path (the TU includes no iostream/spdlog; `MapMinioFailure` never concatenates `S3ClientConfig` fields — T-3-03); the unique_ptr→shared_ptr seam is instantiated inside `MinioS3Client.cpp` where the type is complete, with the out-of-line `~MinioS3Client() = default;` exported from the library, so out-of-tree consumers never need the uninstalled internal header. `tlsVerify` defaults true (T-3-02).
