<objective>
Introduce the structured error-surfacing plumbing that RENDER-09 and D-25/D-26/D-27/D-28 require, and close the SPIR-V wire-format gap RESEARCH.md's Pitfall 6 flags (entry_point strings currently dropped by `SerializeCompiledStages()`), before any RenderProcessor Vulkan mechanics are written in plans 03-03..03-06. This plan touches no Vulkan API surface at all — it is pure data-shape and dispatch-gate work in `ProcessingManager`/`ProcessingResult`, done first specifically so every later plan has a stable error type and wire format to target instead of improvising one mid-implementation.

Per D-28's deliberate scope-broadening (confirmed, not scope creep — see 03-CONTEXT.md), the new dispatch gate is applied uniformly to both the render path and the existing MNN dispatch path in the same `Process()` call site. Grep evidence (`grep -rn "return ProcessingResult{}" SuperGenius/SGProcessingManager/src/processors/`) confirms all 15 MNN processor files' existing failure returns already leave `ProcessingResult::hash` as a default-constructed *empty* vector (size 0) — not a 32-byte zero-filled vector — and every MNN success path (e.g. `processing_processor_mnn_image.cpp:99-101`) always assigns a real, non-empty `SHA256_DIGEST_LENGTH`-sized hash. This means D-28's "retroactive MNN fix" can be satisfied by having the gate treat an **empty** `hash` as an additional failure signal alongside the new structured `error` field — with zero changes to any of the 15 MNN processor files. This is the proportional, evidence-grounded implementation of D-28, not a scope reduction: it fixes the exact bug D-28 describes (a failed result silently flowing through to `FileManager::SaveASync`/the hash-return path) without expanding this phase's blast radius into 15 unrelated files that RENDER-01..09/DETV-01/02 never asked to touch.

Purpose: Give every later plan (03-02..03-06) a stable, already-wired error type and wire format so RenderProcessor's Vulkan implementation work never has to invent or renegotiate either.
Output: `ProcessingResult` gains a structured `error` field; `ProcessingManager::Process()` gains a failure gate; `SerializeCompiledStages()` carries entry_point strings.
</objective>
