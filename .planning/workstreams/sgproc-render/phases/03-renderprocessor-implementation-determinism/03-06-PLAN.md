<objective>
Deliver the literal, empirical proof DETV-01 requires: the same render pass definition executed N≥10 times on the same node produces a bit-exact matching output hash every time. Every prior plan in this phase (03-01 through 03-05) built the architectural guards DETV-02 requires (explicit clears, VK_SAMPLE_COUNT_1_BIT, fixed-function pipeline state, no dynamic state) — this plan is where that architecture is actually exercised against real, working Vulkan hardware for the first time in this codebase, and where the empirical claim is either confirmed or falsified. Per RESEARCH.md's Metadata section: "'bit-exact across N≥10 runs' is an empirical claim only the phase's own repeat-run test can actually prove."

**New fixture, not a retrofit of Phase 2's fixtures (documented, per plan 03-04's scalar-component-format decision):** Phase 2's `dummy_shader.glsl` declares `vec3 inPosition`, which this schema's `vertex_layout_entry.format` (scalar-only: `FLOAT16`/`FLOAT32`/`INT32`, no vec2/vec3/vec4 variant) cannot actually describe — that fixture was authored only for Phase 2's compile-validate testing and was never meant to be pipeline-executed. This plan authors a new, additional vertex shader with a scalar `float inPosition` attribute instead, consistent with plan 03-04's documented schema reading. Phase 2's original fixtures and their tests are untouched.

**Two determinism guards this plan's fixture — not RenderProcessor's C++ code — is responsible for demonstrating:** DETV-02 lists "fixed shader precision qualifiers" and "no unordered parallel-reduction shader math" among its architectural guards. Both are properties of job-*authored* GLSL source, not something `RenderProcessor`'s C++ code can inspect or enforce on arbitrary job-supplied shaders (there is no shader-source static-analysis step anywhere in this phase's scope, and adding one is disproportionate — RENDER-01/02's `spirv-val` gate, already enforced in Phase 2, validates SPIR-V well-formedness, not authoring style). This plan's own new fixture shaders are simply authored to satisfy both guards (explicit `precision highp float;`, a trivial single-value assignment with no loop/reduction), demonstrating the guard is achievable and giving DETV-01's repeat-run test a shader that cannot itself be a source of non-determinism.

Purpose: Prove, empirically, on real hardware, that this phase's entire architectural determinism story actually holds — the one claim RESEARCH.md flagged as unverifiable by research alone.
Output: A new, minimal, actually-renderable happy-path fixture, and the N≥10 repeat-run test that either confirms or surfaces a real determinism bug in plans 03-01..03-05's implementation.
</objective>
