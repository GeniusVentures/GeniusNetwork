<objective>
Build RenderProcessor's non-Vulkan-device-touching resource layer: parsing plan 03-01/03-02's wire formats back into usable in-memory data, resolving uniform values (D-29/D-30's push-constant/descriptor-set threshold decision), and the Vulkan buffer/image allocation primitives (D-18..D-21) every later plan will call. This plan also introduces the single ordered-teardown mechanism (D-22/D-24) that plans 03-04/03-05 extend as they create render passes, pipelines, and command buffers — established here, once, rather than reinvented per plan.

No `RenderPass`/`Pipeline`/draw/readback code is written in this plan — those depend on data this plan produces (parsed stages, resolved uniforms, allocated buffers) and are built in plans 03-04/03-05. `StartProcessing()` itself is not yet rewired to call any of this plan's helpers — that full wiring happens in plan 03-05, once every helper it needs exists.

Per RESEARCH.md's Pitfall 3 (std430 push-constant/UBO padding), uniform packing in this plan restricts itself to the schema's `DataType` scalar/vector types using natural 4-byte-aligned packing per declared type (no arbitrary struct nesting is possible from this schema — `RenderShaderUniform` is a flat name→value map), avoiding the vec3-padding trap by packing each uniform at a 16-byte-aligned offset regardless of its declared type's natural size (the simplest correct choice available, at the cost of some wasted padding — acceptable given the 128-byte D-29 threshold is small and jobs with many uniforms fall back to the descriptor-set path anyway).

Purpose: Give plans 03-04/03-05 fully-resolved, already-validated in-memory data and Vulkan resource primitives to build the actual pipeline/draw/readback on top of.
Output: RenderProcessor gains wire-format parsers, uniform resolution, dedicated buffer/image allocation helpers, and the ordered teardown stack.
</objective>
