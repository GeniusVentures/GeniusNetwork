    Replace quantization.cpp's QuantizeFloatBuffer body with a per-element loop over `data[0..count)`. For each element x, extract its bit pattern into a uint32_t via std::memcpy (never a reinterpret_cast type-pun), then apply these branches in this exact order, as an if / else-if chain -- the order itself is the D-07 requirement ("explicit first branch, before any rounding arithmetic"), not just the individual checks:
    1. Denormal check (D-07): exponent bits (bits & 0x7F800000u) == 0 AND mantissa bits (bits & 0x007FFFFFu) != 0 -- covers both signs. If true: write 0.0f back (canonical +0.0, D-08).
    2. std::isnan(x): write bit pattern 0x7FC00000 back via memcpy (D-09 -- the hardcoded literal, never std::numeric_limits<float>::quiet_NaN()).
    3. std::isinf(x): write 0x7F800000 if std::signbit(x) is false, else 0xFF800000 (D-06 -- two distinct patterns, never collapsed).
    4. x == 0.0f (covers both +0.0 and -0.0 under IEEE equality, D-08): write 0.0f back.
    5. else: data[i] = std::round(x * kScale) / kScale, where kScale is a constexpr float equal to 1048576.0f (2^20, D-05).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job definition (model/shader source_uri_param) -> processor output bytes | Untrusted job content flows through QuantizeFloatBuffer/QuantizeByteBuffer before ever reaching sha256() -- this is the tolerance-vs-integrity boundary the whole milestone centers on. |
| MNN tensor output (host<float>()) -> QuantizeFloatBuffer -> sha256() | Real cross-hardware float divergence enters here; canonicalization branch order determines whether special values reintroduce the exact divergence quantization exists to remove. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Tampering | quantization.cpp QuantizeFloatBuffer rounding grid (S=2^20) | critical | mitigate | Grid step (~1e-6) is kept as tight as Phase 11's empirical data allows (~10x margin over measured maxAbsDelta, not loosened further without new data); Plan 12-02's SECV-01 counter-test independently proves this tolerance still rejects a substituted MNN model. |
| T-12-02 | Tampering | QuantizeFloatBuffer NaN/Inf/denormal/zero canonicalization order | high | mitigate | Denormal/NaN/Inf/zero checks are explicit if/else-if branches evaluated strictly before the rounding else-branch (D-07), preventing hardware/compiler-dependent special-value corruption from reintroducing cross-machine divergence (Pitfall 1); verified by quantization_test.cpp's exact-bit-pattern assertions. |
| T-12-03 | Tampering | Hash-layer consistency (chunk hash / final hash / ComputeArtifactIdentity) | medium | mitigate | Task 2's new output_hashing_test.cpp case uses rawOutputCapture to prove the processor's own hashed bytes and ComputeArtifactIdentity's independent re-hash of the same bytes agree, closing the "quantize only one visible layer" gap (Pitfall 5). |
| T-12-04 | Repudiation | ExecutionManifest.executorIdentity / gpuMemoryUsedBytes | low | accept | Explicitly out of scope (D-01/D-02); this plan makes zero changes to ComputeManifestHash/ExecutionManifest, so no repudiation surface is introduced or altered. |
| T-12-05 | Denial of Service | Per-element branching added to QuantizeFloatBuffer's hot per-window MNN loop | low | accept | Branching is O(1) per float element with no new allocation or nested loop; matches the existing already-wired per-window call pattern from Phase 10 (PITFALLS.md Performance Traps). |
