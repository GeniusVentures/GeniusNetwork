<objective>
Define the C++ struct types for typed artifact records and execution manifests — the data contracts that all subsequent plans build against. Implement SHA-256 content-hash computation for individual artifacts (not manifest-level hashing, which needs serialization from Plan 08-02).

Output: Two new headers — `include/artifacts/artifact_types.hpp` and `include/artifacts/execution_manifest.hpp` — with complete struct definitions and inline content-hash computation.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Processor output → Artifact contentHash | Raw bytes crossing from processor (potentially attacker-controlled if job input is malicious) into hash computation — hash algorithm selection is critical |
| Chunk hash array → Artifact::chunkHashes | Existing processor-produced hashes stored into fixed-size inline array — overflow protection needed |
| Manifest field population → Serialize() | All manifest fields populated by ProcessingManager before serialization — zero-initialization required for deterministic output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | Artifact::ComputeArtifactIdentity | mitigate | Uses SHA-256 from existing sgprocmanagersha::sha256 — no new hash path introduced; identical code path to Phase 06 executor identity hashing |
| T-08-02 | Denial of Service | Artifact::AddChunkHash | mitigate | Bounds-check: returns false when chunkHashCount >= 1024; caller must handle overflow |
| T-08-03 | Information Disclosure | ExecutionManifest::manifestHash | mitigate | manifestHash computed from Serialize() bytes — Plan 08-02 must zero manifestHash before serialization to avoid self-referential hashing |
| T-08-04 | Elevation of Privilege | TerminalState enum | accept | Plain enum with no auth semantics — only describes execution outcome, no privilege escalation path |
| T-08-SC | Tampering | Header-only design | accept | No new npm/pip/cargo packages — C++ standard library and existing sha256.hpp only |
</threat_model>
