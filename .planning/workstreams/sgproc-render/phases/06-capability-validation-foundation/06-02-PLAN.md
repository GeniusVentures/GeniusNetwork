**Flow (per D-03 async pattern):** All checks run synchronously against the cached snapshot (no I/O needed — all data is cached from BuildSnapshot). The callback is invoked at the end. **Step 1 — PassType check (CAP-04/D-04):**
- Look up `pass.get_type()` in `m_impl->snapshot.executorCaps` (which was populated from passFactories in BuildSnapshot).
- If not found: add `UnmetRequirement{UnmetRequirementCategory::PASS_TYPE, "No executor registered for PassType " + std::to_string(static_cast<int>(pass.get_type())) + ". Available: [" + listAvailablePassTypes() + "]"}`.
- List available pass types by iterating snapshot.executorCaps and joining their PassType names.

**Step 2 — Vulkan feature/limit check (CAP-02/D-14):**
Only for PassType::RENDER (only render passes use Vulkan directly). Check the seven critical limits (D-14) against `snapshot.vulkanProps.limits`:

| Limit Field | Check Against |
|---|---|
| `maxImageDimension2D` | `pass.get_render_target()->get_width()`, `get_height()` |
| `maxBufferSize` | vertex buffer size + index buffer size from `pass.get_vertex_buffer()` |
| `maxPushConstantsSize` | total uniform packed bytes (estimate from `render_shader.get_uniforms()`) |
| `maxUniformBufferRange` | same uniform estimate (for descriptor-set fallback) |
| `maxColorAttachments` | 1 (single render target — always satisfied if ≥1) |
| `maxPerStageDescriptorSamplers` | uniform count (each uniform is ≤1 sampler) |
| `maxMemoryAllocationCount` | estimated allocation count: 1 framebuffer + 2 buffers (vertex+index) + 1 pipeline ≈ 4 |

Each unmet limit produces: `UnmetRequirement{UnmetRequirementCategory::VULKAN, "limitName: need X, have Y"}`.

Also check device type: must be DISCRETE_GPU or INTEGRATED_GPU (reuse `RenderProcessor::IsAcceptable()` — make it accessible or duplicate the predicate). If not: `UnmetRequirement{UnmetRequirementCategory::VULKAN, "Device type not acceptable (need DISCRETE_GPU or INTEGRATED_GPU)"}`.

**Step 3 — If any unmet requirements, invoke callback with `CanExecuteResult{false, "", unmet}` and return.**

If all pass:
- Derive executorId from snapshot.identityHash: `"sgproc-" + hex(identityHash[0..7])` (first 8 bytes as hex, per D-08).
- Invoke callback with `CanExecuteResult{true, executorId, {}}`.

**Step 3 — GPU memory estimation (CAP-05/D-15):**

Only for PassType::RENDER:
- Estimate render target memory: `width * height * bytesPerPixel(colorFormat) + width * height * bytesPerPixel(depthFormat)`.
- Estimate buffer memory: vertex buffer size + index buffer size.
- Estimate pipeline overhead: fixed 64MB (conservative — covers pipeline cache, descriptor pools, command buffers).
- Total estimate = renderTargetMem + bufferMem + 64MB.
- Check against largest device-local heap from `snapshot.memProps`: iterate heaps where `VK_MEMORY_HEAP_DEVICE_LOCAL_BIT` is set, find max `size`.
- If total > largestHeap: `UnmetRequirement{UnmetRequirementCategory::RESOURCE, "Estimated GPU memory " + formatBytes(total) + " exceeds largest device-local heap " + formatBytes(largestHeap)}`.

For PassType::INFERENCE:
- Skip GPU memory check (MNN manages its own memory pools; per RESARCH.md, MNN's internal allocator handles this).

**Step 4 — Disk space check (CAP-05/D-16):**

For ALL pass types:
- Estimate output artifact size: for RENDER, `width * height * bytesPerPixel(colorFormat)`; for INFERENCE, use input dimensions × format bytes; otherwise 0.
- If `snapshot.availableDiskBytes > 0` and `estimatedOutputSize > snapshot.availableDiskBytes`: `UnmetRequirement{UnmetRequirementCategory::RESOURCE, "Estimated output size " + formatBytes(estimatedOutputSize) + " exceeds available disk space " + formatBytes(snapshot.availableDiskBytes)}`.
- If `snapshot.availableDiskBytes == 0`: skip check (degraded mode from BuildSnapshot query failure).

**Step 5 — Executor identity (CAP-06/D-08):**

Already computed in BuildSnapshot (Plan 06-01). In CanExecute, derive executorId from the cached hash:
```cpp
std::string executorId = "sgproc-";
char hex[3];
for (size_t i = 0; i < std::min(size_t(8), snapshot.identityHash.size()); ++i) {

    executorId += hex;
}
```

This is deterministic — same snapshot → same hash → same executorId.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job definition (SgnsPass) → CanExecute | Untrusted input — malformed pass could have missing fields, invalid dimensions |
| CapabilitySnapshot → CanExecute | Trusted — built once at startup from Vulkan driver + registry (same process) |
| File system → disk space check | Advisory — TOCTOU between check and actual write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04 | Denial of Service | CanExecute with null/missing pass fields | mitigate | All pass field accesses use `get_*()` optional checks before dereference; missing fields → skip that check category (not crash) |
| T-06-05 | Elevation of Privilege | Malicious pass claiming unsupported but passing check | mitigate | Each check independently validates against snapshot; no single bypass path |
| T-06-06 | Information Disclosure | executorId revealing hardware info | accept | 8-byte hex prefix of SHA-256 is not reversible to device identity; same level of exposure as device name string already sent over gRPC |
| T-06-07 | Denial of Service | Integer overflow in GPU memory estimation | mitigate | Use `uint64_t` for all memory calculations; check for overflow before comparison |
</threat_model>
