<objective>
Refactor `thirdparty/build/CommonTargets.cmake` to build the four render-specific thirdparty libraries (SPIRV-Headers, SPIRV-Tools, shaderc, vk-bootstrap) unconditionally for all platforms including Android and iOS, while keeping Vulkan-Headers and Vulkan-Loader gated to desktop platforms only.

Purpose: Make the render dependency chain available for Android (arm64-v8a, armeabi-v7a) and iOS (arm64) cross-compilation builds. Per D-02, vk-bootstrap/SPIRV-Headers/SPIRV-Tools/shaderc are platform-agnostic C++ and must be pulled out of the `if(NOT ANDROID)` guard; only Vulkan-Headers + Vulkan-Loader remain platform-gated because the NDK provides them on Android and MoltenVK provides them on Apple platforms.

Output: `thirdparty/build/CommonTargets.cmake` with render libraries in unconditional blocks and platform-conditional Vulkan dependency wiring for vk-bootstrap.
</objective>

    - SuperGenius/build/iOS/CMakeLists.txt (lines 35-36 — the same MoltenVK Vulkan variable pattern reused at SuperGenius level)
  </read_first>
  <action>
    Wire vk-bootstrap's `VulkanHeaders_DIR` and `Vulkan_LIBRARY` per platform, before the vk-bootstrap ExternalProject_Add block:

    1. **Desktop (Windows/Linux/macOS)** — keep the existing logic:
       - `VulkanHeaders_DIR` = `${CMAKE_CURRENT_BINARY_DIR}/Vulkan-Loader/share/cmake/VulkanHeaders`
       - This is already set inside the `if(NOT ANDROID)` block. After Task 1's refactoring, Vulkan-Headers/Vulkan-Loader are in `if(NOT ANDROID)`, so their `VulkanHeaders_DIR` is naturally only available on desktop. The vk-bootstrap block needs this value.
       - Set a variable `_VK_BOOTSTRAP_VULKAN_HEADERS_DIR` conditionally:
         - `if(NOT ANDROID AND NOT IOS)`: `set(_VK_BOOTSTRAP_VULKAN_HEADERS_DIR "${CMAKE_CURRENT_BINARY_DIR}/Vulkan-Loader/share/cmake/VulkanHeaders")`

    2. **Android** — NDK provides Vulkan via `find_package(Vulkan)`:
       - The NDK's `find_package(Vulkan)` creates `Vulkan::Vulkan` and sets `Vulkan_INCLUDE_DIRS`. But vk-bootstrap's CMakeLists.txt does `find_package(VulkanHeaders)` specifically, not `find_package(Vulkan)`.
       - Strategy: Build Vulkan-Headers from source for Android too. Add `ExternalProject_Add(Vulkan-Headers ...)` inside an `if(ANDROID)` block (separate from the desktop one), installing headers to a known prefix. Then set `_VK_BOOTSTRAP_VULKAN_HEADERS_DIR` to that prefix's CMake config.
       - OR, if you determine the NDK's Vulkan headers include a usable CMake config at a known path, use that. The NDK typically places Vulkan headers at `${CMAKE_ANDROID_NDK}/sources/third_party/vulkan` — check if a `VulkanHeadersConfig.cmake` or similar exists there.
       - `if(ANDROID)`: `set(_VK_BOOTSTRAP_VULKAN_HEADERS_DIR <resolved-path>)` — use the approach that requires the least additional build complexity.

    3. **iOS** — MoltenVK provides Vulkan headers at `${CMAKE_CURRENT_BINARY_DIR}/moltenvk/build/include`:
       - MoltenVK's build does NOT install a `VulkanHeadersConfig.cmake` — it only provides raw headers.
       - Strategy: Build Vulkan-Headers from source for iOS too (separate `if(IOS)` block), installing to a known prefix. Then set `_VK_BOOTSTRAP_VULKAN_HEADERS_DIR` to that prefix.
       - `if(IOS)`: Add `ExternalProject_Add(Vulkan-Headers ...)` then `set(_VK_BOOTSTRAP_VULKAN_HEADERS_DIR "${CMAKE_CURRENT_BINARY_DIR}/Vulkan-Headers/share/cmake/VulkanHeaders")`
       - This Vulkan-Headers build MUST depend on nothing (no DEPENDS clause) since MoltenVK is built separately in iOS/CMakeLists.txt before CommonTargets.cmake is included.

    4. For the vk-bootstrap ExternalProject_Add block, replace the hardcoded `-DVulkanHeaders_DIR:PATH=${CMAKE_CURRENT_BINARY_DIR}/Vulkan-Loader/share/cmake/VulkanHeaders` with `-DVulkanHeaders_DIR:PATH=${_VK_BOOTSTRAP_VULKAN_HEADERS_DIR}`.

    5. Also add `-DVulkan_LIBRARY:PATH=...` to vk-bootstrap's CMAKE_CACHE_ARGS for iOS, since vk-bootstrap may need it. Use the MoltenVK library path from iOS/CMakeLists.txt's pattern: `${CMAKE_CURRENT_BINARY_DIR}/moltenvk/build/lib/MoltenVK.xcframework`.

    6. For the `DEPENDS` clause of vk-bootstrap: on desktop, keep `DEPENDS Vulkan-Headers`. On Android/iOS, if you added a separate Vulkan-Headers build, `DEPENDS Vulkan-Headers`. Otherwise use `DEPENDS` with no Vulkan-Headers.

    **Key constraint (D-03):** Do not modify any existing non-render ExternalProject_Add block. Only add new blocks and modify vk-bootstrap's CMAKE_CACHE_ARGS.
  </action>

    - On Android: `_VK_BOOTSTRAP_VULKAN_HEADERS_DIR` resolves to a path where Vulkan headers exist (either NDK's or a locally-built Vulkan-Headers install)
