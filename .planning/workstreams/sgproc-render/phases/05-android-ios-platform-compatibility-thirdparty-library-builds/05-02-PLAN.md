    Create `thirdparty/build/mobile/README.md` with the following sections. Use concrete paths and commands — no placeholder values.

    **Section 1: Prerequisites**
    - Android: NDK (r26 or later recommended), CMake ≥ 3.22, Python 3.7+ (for shaderc's glslang code generation — D-06), Ninja (optional but recommended)
    - iOS: Xcode (15+ with command-line tools), CMake ≥ 3.22, Python 3.7+ (for shaderc)
    - Both: Git (submodules must be initialized: `git submodule update --init --recursive`)

    **Section 2: Android Build Commands**
    - Create build directory: `mkdir -p thirdparty/build/Android/Debug && cd thirdparty/build/Android/Debug`
    - CMake configure for arm64-v8a:
      ```
      cmake .. -G "Ninja" \
        -DCMAKE_BUILD_TYPE=Debug \
        -DCMAKE_ANDROID_NDK=/path/to/ndk \
        -DANDROID_ABI=arm64-v8a
      ```
    - CMake configure for armeabi-v7a (D-07): same but `-DANDROID_ABI=armeabi-v7a`
    - Build: `cmake --build . --parallel 8`
    - Note: `--parallel` value should be based on `nproc`/available cores

    **Section 3: iOS Build Commands**
    - Create build directory: `mkdir -p thirdparty/build/iOS/Debug && cd thirdparty/build/iOS/Debug`
    - CMake configure for arm64 device (D-08):
      ```
      cmake .. -G "Xcode" \
        -DCMAKE_BUILD_TYPE=Debug \
        -DCMAKE_TOOLCHAIN_FILE=../apple.toolchain.cmake \
        -DPLATFORM=OS64 \
        -DDEPLOYMENT_TARGET=15
      ```
    - Build: `cmake --build . --config Debug --parallel 8`
    - Alternatively with Ninja (if preferred): use `-G "Ninja"` instead of `-G "Xcode"`

    **Section 4: Expected Build Outputs**
    - List the four render libraries and their expected output paths:
      - vk-bootstrap: `thirdparty/build/{Android|iOS}/Debug/vk-bootstrap/lib/libvk-bootstrap.a`
      - SPIRV-Tools: `thirdparty/build/{Android|iOS}/Debug/SPIRV-Tools/lib/libSPIRV-Tools.a`
      - shaderc: `thirdparty/build/{Android|iOS}/Debug/shaderc/lib/libshaderc_combined.a`
      - Vulkan Loader (Android): provided by NDK — `libvulkan.so` on device, linked at runtime
      - Vulkan Loader (iOS): `thirdparty/build/iOS/Debug/moltenvk/build/lib/MoltenVK.xcframework`

    **Section 5: Link Verification**
    - After building thirdparty libraries, the SGProcessingManager render path can be verified by configuring SuperGenius for the target platform:
      - Android: `SuperGenius/build/Android/` — cmake configure should find all four render library targets without errors
      - iOS: `SuperGenius/build/iOS/` — cmake configure should find all four render library targets without errors
    - A successful configure (no `find_package` or `target_link_libraries` errors) proves the link chain is intact.
    - Build logs should be captured as evidence per D-10.

    **Section 6: Troubleshooting**
    - shaderc build fails with "Python not found": ensure Python 3.7+ is on PATH (D-06 — Python needed for glslang code generation)
    - SPIRV-Tools build fails on Android: verify `ANDROID_STL=c++_static` is propagated through `_CMAKE_COMMON_CACHE_ARGS`
    - vk-bootstrap configure fails with "VulkanHeaders not found": check `_VK_BOOTSTRAP_VULKAN_HEADERS_DIR` resolution in CommonTargets.cmake
    - Build runs out of memory: reduce `--parallel` value; shaderc's glslang build is memory-intensive

    Write the file to `thirdparty/build/mobile/README.md`. Create the `thirdparty/build/mobile/` directory if it does not exist.
