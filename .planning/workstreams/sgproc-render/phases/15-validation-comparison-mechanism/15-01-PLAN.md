## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Job schema `parameters` (quantScale/byteQuantMode) -> tolerance-derivation functions | Attacker-influenceable input (a job author in this project's distributed/P2P processing context) crosses into the numeric-tolerance-threshold decision this plan's functions make -- the same trust boundary Phase 14 already established for `ResolveQuantScale`/`ResolveByteQuantMode`, now extended into a second, related decision (tolerance, not just quantization grid). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-01 | Tampering | ComputeFloat32Diff/ComputeUint8Diff extraction | low | accept | Pure code relocation with an identical implementation, verified byte-for-byte via diff_utils_test's known-delta cases; `capture_diff` is an offline diagnostic CLI, not a network-exposed runtime component, so extraction itself introduces no new attack surface. |
| T-15-02 | Tampering | IsFloatChunkWithinTolerance/IsByteChunkWithinTolerance's D-03 grid-step/mask-bound formula | high | mitigate | The formula (2/S for float, (1&lt;&lt;N)-1 for byte) is the single most safety-critical new decision this phase introduces -- too loose and a genuine defect could hide behind it in Plan 15-02/15-04. Mitigated by: (1) the "zero elements may exceed threshold" comparison policy (not a percentage-based bar, per RESEARCH.md's A4), enforced by `statsOut.maxAbsDelta &lt;= tolerance` rather than any averaged stat; (2) diff_utils_test's explicit passing/failing boundary-pair cases for both formulas; (3) Plan 15-04's SECV-02 full-pipeline counter-test provides the final, empirical proof against a real corrupted MNN model. |
| T-15-03 | Tampering | TryGetDeclaredQuantScale/TryGetDeclaredByteQuantMode's own parameter-lookup validation | medium | mitigate | Duplicates quantization.cpp's exact validated-lookup discipline (type check, numeric check, power-of-two/range check) rather than trusting a caller-supplied raw value -- an adversarial job cannot force an invalid/degenerate `quantScale`/`byteQuantMode` value through to the tolerance formula; any invalid declaration falls back to D-04's fixed constants instead. |
