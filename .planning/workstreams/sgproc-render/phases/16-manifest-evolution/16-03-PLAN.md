<objective>
Close the structural gap RESEARCH.md's Critical Finding identified: today, `ProcessingManager::ProcessInternal()` never constructs an `ExecutionManifest` on any error path — every `CANCELLED`/`TIMED_OUT`/`BUDGET_EXCEEDED`/generic-error branch returns `outcome::failure(...)` before the manifest-assembly block ever runs. Add a `GetLastManifest()` accessor (mirroring the existing `GetProgress()` precedent) backed by a new `m_lastManifest` member that is populated with a minimal manifest — including the new `errorMessage` field Plan 16-02 added — on every terminal path, not just success.

Purpose: ARTF-09's success criterion ("retrievable from the manifest artifact by a caller that only has the manifest, not the original error site") is unsatisfiable by a struct-field addition alone; it requires this control-flow fix. Per RESEARCH.md's evaluation of three design options, the chosen approach (Option 3 — a new additive accessor) makes zero changes to the existing `outcome::result<ProcessOutput>` contract or to `processing_core_impl.cpp`, the only real production caller — the lowest-risk mechanism for a "deferred gap closure" phase.
Output: `ProcessingManager::GetLastManifest()`, backed by `m_lastManifest`, reachable and correctly populated after every terminal state — proven against the existing `processing_conformance_cancellation` suite's real CANCELLED and BUDGET_EXCEEDED fixtures, plus a new success-path case.
</objective>
