<objective>
Add ExecutionManifest's new `errorMessage` field (ARTF-09) and the append-only trailer versioning mechanism (ARTF-10) that makes adding it — and any future field — possible without breaking the existing fixed-offset binary format or its hardcoded-literal round-trip tests.

Purpose: today's `SerializeManifest`/`DeserializeManifest` hard-fail on any size mismatch and have no version/magic field anywhere (Phase 08 D-04/D-05) — this is the first phase to introduce any schema flexibility into that format. Getting the trailer's bounds-checking right is the one genuine security-relevant surface this phase introduces (ASVS V5): every conditional trailer read must be gated by its own explicit `bytes.size()` check before the corresponding read, so a truncated/corrupted blob cannot trigger an out-of-bounds memcpy.
Output: `ExecutionManifest` with a new `errorMessage[256]` field; `SerializeManifest`/`DeserializeManifest` extended with a bounds-checked, append-only `schemaVersion`+`errorMessage` trailer; 3 new tests proving the field round-trips/truncates correctly and both SC4 compatibility directions hold.
</objective>
