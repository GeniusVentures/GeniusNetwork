<objective>
Prove, via an actual repeated concurrent-execution test (not code review alone), that plan 01-01's migration and plan 01-04's `RenderProcessor` genuinely serialize through the one shared `VulkanInitMutex()` under real concurrent load — this is D-05, the required verification for CTX-02's Decision Flag #1 (loader-level thread-safety does not imply driver-level concurrent-init safety; MNN's own pre-existing defensive mutex is the stronger, empirically-grounded signal per RESEARCH.md).

**Scope note on MNN_Image coverage**: This test directly and concurrently exercises `MNN_String`, `MNN_Volume`, and `RenderProcessor` — 3 distinct call sites through the identical shared `VulkanInitMutex()` accessor function. `MNN_Image`'s call site is not separately runtime-exercised here because no fully-local, network-free `MNN_Image` (posenet) test fixture exists anywhere in this repository today — the only existing image-processing job definition (`test/src/processing_schema/posenet-processing-job.json`) fetches its model and image data over the network from IPFS, which would make this repeatable stress test's pass/fail signal depend on network availability unrelated to the Vulkan-init race being tested. `MNN_Image`'s migration to the exact same `VulkanInitMutex()` function is already structurally verified in plan 01-01, Task 2 — because all 4 call sites call the literal same shared mutex-accessor function, and mutual-exclusion correctness of that primitive does not depend on which specific caller acquires it, demonstrating correct serialization for 3 concurrent distinct callers is sufficient evidence that a 4th caller using the identical accessor is equally serialized. This rationale is recorded here rather than silently omitting the coverage.

Purpose: Close CONTEXT.md's D-05 requirement with a real, repeatable, automated test artifact, not a design-only exercise.
Output: `test/src/processing_vulkan_concurrency/` — a new GTest target exercising concurrent Vulkan init across 3 distinct real call sites, repeated across many iterations.
</objective>
