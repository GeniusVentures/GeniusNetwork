<objective>
Wire the quantize-then-capture-then-hash pattern into the 7 "chained" MNN processor types (Bool, Buffer, Image, String, Texture1D, TextureCube, Volume) -- the sub-family whose combined per-subtask hash is a rolling hash-of-hashes (`subTaskResultHash = sha256( previousHashBytes + currentChunkHashHex )`), not an independent re-quantizable float array. Each of these 7 files needs exactly 1 insertion point (chunk-hash), except TextureCube which needs 2 (it has two separate chunk-hash call sites, one per code branch).

Purpose: complete Phase 10's per-file wiring for the remaining MNN sub-family. Confirmed via direct source read (not assumed from research alone) that these 7 files' second sha256 call is a pure hash-of-already-quantized-hash-bytes, so no second insertion point exists here -- adding one would be dead/meaningless code per ARCHITECTURE.md Anti-Pattern 3.
Output: 7 modified processor files, each quantizing (identity stub) and capturing at its chunk-hash call site(s) only.
</objective>
