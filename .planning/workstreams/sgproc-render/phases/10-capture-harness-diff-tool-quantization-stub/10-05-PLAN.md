capture_diff.cpp CLI design: required flags `--a <path>` and `--b <path>` (the two `.cap` files to compare) and `--element-type <float32|uint8>` (which raw-byte interpretation to use for the per-element numeric stats -- `float32` for the MNN fixture's capture files, `uint8` for the render fixture's, per Plan 10-CONTEXT.md's discretion note deferring exact CLI shape); optional `--json-output <path>` (default `diff_report.json`).

DIFF-03 (hash-match booleans, computed purely from artifact/manifest metadata -- no raw-byte decoding needed): `contentHashMatch` = byte-compare `artifacts[0].contentHash` between the two files; `chunkHashesMatch` = a per-index boolean vector comparing `artifacts[0].chunkHashes[j]` for `j` in `[0, min(chunkHashCount_a, chunkHashCount_b))`; `combinedHashMatch` = byte-compare the two `CaptureFile::combinedHash` vectors. Report all three explicitly and separately from the numeric stats below -- this satisfies DIFF-03 independently of DIFF-01/02.

DIFF-01/02 (per-element numeric divergence): take the LAST `CaptureRecord` in `rawRecordsPerArtifact[0]` from each file (the final/combined-or-only output bytes -- the same bytes that fed each run's `contentHash`), specifically each record's `quantizedBytes` field (the bytes production hashing actually saw). If the two buffers' byte lengths differ, report this as a size-mismatch error and skip the per-element pass (still report the DIFF-03 hash booleans above). Otherwise, reinterpret per `--element-type`: for `float32`, treat the buffer as a contiguous `float` array (`byteCount / 4` elements) and for each element pair compute `absDelta = std::fabs( a - b )`; `relDelta = absDelta / std::max( { std::fabs( a ), std::fabs( b ), 1e-6f } )` (named constant `kRelativeDeltaEpsilonFloor = 1e-6f`, avoids divide-by-zero near zero-valued elements); `ulpDistance` via the standard ordered-integer bit-reinterpretation technique (reinterpret each float's 4 bytes as `int32_t`; if the bit pattern is negative, transform it to `0x80000000 - bits`, otherwise leave it unchanged; the ULP distance is the absolute value of the two transformed values' difference, computed in `int64_t` to avoid overflow); an element "exceeds threshold" if `relDelta > kDefaultFloatRelativeThreshold` (named constant, `1e-4`; per D-07, this is a fixed default value, not a CLI-configurable flag -- the exact number is a small documented epsilon per Plan 10-CONTEXT.md's discretion note, since Phase 10's quantization is a no-op stub, so this exists only to exercise the reporting mechanism, not to make a real cross-hardware precision claim; Phase 12 revisits this value). For `uint8`, treat the buffer as a flat byte array and for each element pair compute `absDelta = std::abs( int(a) - int(b) )`; `relDelta = absDelta / static_cast<double>( std::max( { static_cast<int>(a), static_cast<int>(b), 1 } ) )`; `ulpDistance = absDelta` (each representable value is exactly 1 ULP apart in an 8-bit integer domain); "exceeds threshold" if `absDelta > kDefaultByteAbsoluteThreshold` (named constant, `1`).

Reduce to whole-buffer summary stats: `maxAbsDelta`, `maxRelDelta`, `maxUlpDistance` (max over all elements), and `percentExceedingThreshold` = `100.0 * exceedingCount / elementCount`.

Output (D-06 -- both formats, not deferred): print a human-readable console summary containing every stat above plus the three DIFF-03 booleans; separately, build an `nlohmann::json` object with the same fields (`elementType`, `elementCount`, `maxAbsDelta`, `maxRelDelta`, `maxUlpDistance`, `percentExceedingThreshold`, `contentHashMatch`, `combinedHashMatch`, `chunkHashesMatch` as a JSON array of booleans) and write it to `--json-output`. Exit code 0 on a successful comparison regardless of how much divergence was found (divergence is data, not a tool failure); exit non-zero only on usage errors or unparseable/incompatible input files.
