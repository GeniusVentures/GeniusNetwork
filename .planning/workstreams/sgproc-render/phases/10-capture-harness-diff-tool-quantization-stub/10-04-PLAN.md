<objective>
Wire the quantize-then-capture-then-hash pattern into `RenderProcessor` (the 14th and final processor file -- the only one hashing uint8 RGBA8/RGB8 readback bytes instead of MNN float32 tensor output), and create the new capture file binary format that Wave 3's `capture_harness`/`capture_diff` will read and write.

Purpose: RenderProcessor has no chunking (`chunkhashes` is explicitly ignored via `(void)chunkhashes;`) and hashes an already-integer, locally-owned buffer -- a structurally simpler single insertion point than any MNN file. The capture file format is the other prerequisite Wave 3 needs: it must not invent a new serialization convention (per D-01) -- it reuses `SerializeArtifact`/`SerializeManifest` unchanged for the metadata+hash portion and appends exactly one new section (the raw pre-/post-quantization bytes) that does not exist anywhere in the codebase today.
Output: RenderProcessor wired; `capture_file_format.hpp`/`.cpp` ready for Wave 3 to build `capture_harness`/`capture_diff` against.
</objective>

`CaptureRecord` holds exactly two fields: `std::vector<uint8_t> preQuantizeBytes;` and `std::vector<uint8_t> quantizedBytes;` -- one instance per `rawOutputCapture` invocation, in call order.

`CaptureFile` holds: `std::string machineIdTag;` (hostname + OS, per D-03), `std::string fixtureLabel;` (e.g. "render-happy-path" or "mnn-float", per D-02), `std::vector<sgns::sgprocessing::Artifact> artifacts;`, `std::vector<std::vector<CaptureRecord>> rawRecordsPerArtifact;` (index-aligned with `artifacts` -- `rawRecordsPerArtifact[i]` is the ordered list of every `rawOutputCapture` call that fed hashes for `artifacts[i]`; for a single-output job, `records[0 .. artifacts[i].chunkHashCount - 1]` correspond 1:1 to `artifacts[i].chunkHashes[0 .. chunkHashCount - 1]`, and an optional trailing record, if present, corresponds to `artifacts[i].contentHash` -- this pairing is what Wave 3's capture_harness self-check (CAPT-02) verifies), `sgns::sgprocessing::ExecutionManifest manifest;`, and `std::vector<uint8_t> combinedHash;` (the job's `ProcessOutput.combinedHash`).

Declare `std::vector<uint8_t> SerializeCaptureFile( const CaptureFile &capture );` and `bool DeserializeCaptureFile( const std::vector<uint8_t> &bytes, CaptureFile &out );`, matching `DeserializeArtifact`/`DeserializeManifest`'s existing bool-return-false-on-malformed-input convention (never throw).

Implement in `capture_file_format.cpp` using this exact little-endian, length-prefixed binary layout (document it in a header doc comment mirroring `artifact_serializer.hpp`'s own "Fixed-field, little-endian" convention note): 4-byte ASCII magic `"SGC1"`; 4-byte little-endian uint32 `machineIdTag` byte-length followed by that many UTF-8 bytes; 4-byte little-endian uint32 `fixtureLabel` byte-length followed by that many UTF-8 bytes; 4-byte little-endian uint32 `artifactCount`; then, per artifact: exactly `ARTIFACT_SERIALIZED_SIZE` bytes from `SerializeArtifact(artifact)` (unchanged, called as-is), 4-byte little-endian uint32 `recordCount` for that artifact, then per record: 8-byte little-endian uint64 `preQuantizeBytes.size()` followed by that many raw bytes, then 8-byte little-endian uint64 `quantizedBytes.size()` followed by that many raw bytes; after all artifacts, exactly `MANIFEST_SERIALIZED_SIZE` bytes from `SerializeManifest(manifest)` (unchanged); finally 4-byte little-endian uint32 `combinedHash.size()` followed by that many raw bytes.

`DeserializeCaptureFile` must validate every length-prefix field against the number of bytes actually remaining in the input buffer BEFORE allocating or reading that many bytes, and must reject (return `false`) any single declared length exceeding 1073741824 (1 GiB) -- both checks close the "malformed capture file triggers unbounded allocation" risk (T-10-02) before it can happen. Return `false` immediately (do not throw, do not partially populate `out`) on: wrong/missing magic, any length-prefix pointing past the buffer's end, any oversized length-prefix, or a truncated `SerializeArtifact`/`SerializeManifest` region.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vulkan readback buffer -> readbackBytes | Locally-owned buffer, safe to mutate in place (no foreign-memory constraint, unlike MNN) |
| Capture file bytes (disk) -> DeserializeCaptureFile | Untrusted input boundary -- a capture file may be hand-edited or corrupted before being fed to capture_diff in Wave 3 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-02 | Denial of Service | DeserializeCaptureFile length-prefixed sections | medium | mitigate | Validate every declared length against remaining buffer size and a 1 GiB cap before allocating; reject with `false` rather than attempting the allocation |
| T-10-01a | Tampering | DeserializeCaptureFile parsing untrusted bytes | medium | mitigate | Never trust a length field without bounds-checking it first; return `false` on any malformed/truncated/oversized input rather than partially populating `out` or reading out of bounds |
| T-10-03 | Information Disclosure | Capture file contents (raw output bytes, hostname) | low | accept | Phase 09's test fixtures are non-sensitive synthetic data; hostname disclosure is equivalent to any local dev-tool log output; this is an offline, hand-shared file between the user's own machines, not a network-exposed artifact |
