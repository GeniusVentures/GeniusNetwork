<objective>
Implement `ShaderCompiler`, a new, standalone, Vulkan-device-free component that compiles job-supplied GLSL to SPIR-V via the now-vendored `shaderc` (plan 02-02) and unconditionally validates the resulting (or directly-submitted) SPIR-V via SPIRV-Tools' `spvtools::SpirvTools::Validate()` before it is ever allowed near `vkCreateShaderModule`.

The single most consequential correctness fact this plan must not get wrong (per 02-RESEARCH.md's Pitfall 2, a load-bearing correction to the workstream-level research): shaderc's public `CompileGlslToSpv` API does **not** run `spirv-val` internally — `GetCompilationStatus() == shaderc_compilation_status_success` only means "glslang's codegen produced *some* SPIR-V," not "SPIRV-Tools' validator approved it." Both code paths through this component — GLSL-compiled and directly-submitted SPIR-V — MUST pass through `spvtools::SpirvTools::Validate()` as an explicit, separate, mandatory second step. Treating "shaderc compiled it" as equivalent to "it's validated" is the single largest correctness risk this phase carries into Phase 3, and this plan's tests exist specifically to catch that mistake.

This component is deliberately Vulkan-device-free (no `VkInstance`/`VkDevice`/`VkPhysicalDevice` member anywhere) — it is pure CPU-side text/bytecode transformation and validation, fully unit-testable in isolation from Phase 1/3's Vulkan context work, per this workstream's own phase-ordering rationale.

Purpose: This is SHADER-01/02/03's actual implementation — the mandatory validation gate that stands between untrusted, job-supplied shader content and the GPU driver.
Output: `include/shaders/shader_compiler.hpp` + `src/shaders/shader_compiler.cpp`, wired into a new standalone `SGShaderCompiler` CMake target, with unit tests proving both the happy path and both rejection paths.
</objective>
