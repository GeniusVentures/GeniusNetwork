<objective>
Extend `capture_diff`'s numeric-diff pass to also examine each individual per-chunk raw capture record (not only the trailing combined-hash record it has been limited to since Phase 10), obtain real chunk-10 numeric divergence data, and honestly characterize that data in `13-SCOPE-BOUNDARY.md` -- without proposing further grid-widening, cross-node consensus plumbing, `ValidateResults` fixes, or schema-configurable precision (all explicitly out of scope per REQUIREMENTS.md's Out of Scope table and 13-CONTEXT.md D-09).

This closes 13-VERIFICATION.md's sole remaining gap: `chunkHashesMatch[10]` is `false` in `captures/diff-mnn-float-refit.json` (post Plan 13-04's S=2^15 grid-widening fix), but `capture_diff`'s existing numeric pass has never been able to say BY HOW MUCH chunk 10 diverges -- only THAT it diverges, via the independent hash comparison. 13-SCOPE-BOUNDARY.md's SC1 Refit "Investigation note" already root-caused this as a real, Phase-10-era scope limitation in `capture_diff.cpp` itself (it only ever numeric-diffs `rawRecordsPerArtifact[0].back()`, never `rawRecordsPerArtifact[0][j]` for `j < chunkHashCount`), and flagged extending the tool as the follow-up path -- this plan is that follow-up.

Purpose: turn an invisible "hash diverges, magnitude unknown" gap into visible, characterized diagnostic data, so whoever next picks up VALD-01's residual 1/15-chunk gap has real numbers to work from instead of a blind spot.
Output: an extended `capture_diff` tool, a fresh diagnostic JSON with chunk 10's real numeric delta, and an honest `13-SCOPE-BOUNDARY.md` update. This plan's job is visibility and honest characterization -- it does not guarantee VALD-01's gap closes, and per the hard constraint below, does not attempt to close it via further grid-widening.

**Hard constraint:** Do NOT propose or implement S=2^16 (or any coarser value) as a fix. S=2^15 was chosen via a confirmed local binary search with exactly one power-of-two step of margin above a CONFIRMED SECV-01 failure boundary (S=2^14 makes `Secv01CounterTest.MnnCorruptedModelStillDiverges` fail deterministically -- see `quantization.hpp` lines 32-63 and 13-04-SUMMARY.md). Going coarser is not a safe option and is out of this plan's scope.
