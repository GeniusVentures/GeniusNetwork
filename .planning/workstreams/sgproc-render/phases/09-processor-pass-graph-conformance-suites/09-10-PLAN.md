<objective>
Close Gap 3 (Non-Deterministic Content Hash, blocker, UAT test 4). The UAT's root-cause note listed this as "possible" MNN-runtime non-determinism (timestamps, random seeds, pointer addresses) requiring investigation. Investigation against the actual `Process()` source (`SuperGenius/SGProcessingManager/src/processingbase/ProcessingManager.cpp`) confirms two concrete, unrelated-to-MNN causes instead — both fixed directly in this plan, no further investigation needed:

1. `ProcessOutput output;` is declared without brace-initialization. `ExecutionManifest` (its `manifest` member) has several `char[]`/`uint8_t[]` fields with no default member initializer (`attemptId`, `taskId`, `subtaskId`, `tokenizerIdentity`, `adapterIdentity`, `quantizationIdentity`, `shaderIdentity`, `manifestHash`, and the unused tail of `inputArtifactHashes`/`outputArtifactHashes`) — these are left holding indeterminate stack memory unless the aggregate is brace-initialized. `SerializeManifest()` (`artifacts/artifact_serializer.cpp`) copies these bytes verbatim into the hashed buffer, so this garbage becomes part of `combinedHash`. (Compare: `Artifact art{};` a few lines later in the same function is *already* brace-initialized — this is the one place that pattern was missed.)
2. The manifest's `startTimeUsec`/`endTimeUsec`/`wallClockUsec` fields are captured from `std::chrono::system_clock::now()` around `StartProcessing()` and are hashed as-is. These are legitimate, intentionally-real wall-clock values (ARTF-04 requires the manifest to record them for provenance) — but they necessarily differ between any two separate `Process()` calls, so hashing them directly makes `combinedHash` non-deterministic by construction, independent of any MNN behavior.

Purpose: fix both without touching `SerializeManifest()`/`ComputeManifestHash()` themselves or the `ExecutionManifest`/`Artifact` struct layouts — both are relied on byte-for-byte by the existing Phase 08 unit tests (`SuperGenius/SGProcessingManager/test/artifacts/artifact_serializer_test.cpp`, which explicitly round-trips real timestamp values through `SerializeManifest`/`DeserializeManifest`); changing their semantics would regress passing tests outside this phase's scope.

Output: `Process()` returns a manifest that still carries real timing for provenance, but whose `combinedHash` (and `manifest.manifestHash`) is computed deterministically.
</objective>

<task type="auto">
  <name>Task 1: Zero-initialize ProcessOutput and exclude volatile timing fields from the manifest hash input</name>
  <files>SuperGenius/SGProcessingManager/src/processingbase/ProcessingManager.cpp</files>
  <action>
Two localized changes inside `ProcessingManager::Process()`:

**1.** Find the local declaration `ProcessOutput output;` (near the `// ── Build ProcessOutput: artifact records + execution manifest (Phase 08) ──` comment, shortly before `const auto &procInput = ...`). Change it to `ProcessOutput output{};` (empty-brace aggregate initialization). `ProcessOutput` and `ExecutionManifest` are both plain aggregates (no user-declared constructors), so this recursively zero-initializes every member without its own default member initializer — including the `ExecutionManifest` fields listed in the objective above — instead of leaving them as indeterminate stack memory. This mirrors the existing `Artifact art{};` pattern used a few lines later in the same function; do not change that line, only the `output` declaration.

**2.** Find where the manifest self-hash is computed (`auto mHash = ComputeManifestHash( manifest ); std::memcpy( manifest.manifestHash, mHash.data(), SHA256_HASH_SIZE ); output.combinedHash = mHash;`, right after the `manifest.outputBytesProduced` accumulation loop). Do not call `ComputeManifestHash` on the live `manifest` directly. Instead: declare a local copy `ExecutionManifest hashInput = manifest;`, set `hashInput.startTimeUsec = 0`, `hashInput.endTimeUsec = 0`, and `hashInput.wallClockUsec = 0` on that copy only, then call `ComputeManifestHash( hashInput )` and assign its result to both `manifest.manifestHash` (via the existing `memcpy`) and `output.combinedHash`. The live `manifest` object returned to the caller (`output.manifest`) keeps its real, unmodified `startTimeUsec`/`endTimeUsec`/`wallClockUsec` — only the *hash input* excludes them. Do not modify `SerializeManifest()`, `DeserializeManifest()`, or `ComputeManifestHash()` themselves (in `artifact_serializer.hpp`/`.cpp`) — those must keep serializing/round-tripping the real timing values byte-for-byte, exactly as `artifact_serializer_test.cpp` already verifies.
