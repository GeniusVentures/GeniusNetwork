<task type="auto">
  <name>Task 1: Fix shared schema fixtures valid-inference.json and valid-render.json</name>
  <files>SuperGenius/test/src/processing_conformance_schema/fixtures/valid-inference.json, SuperGenius/test/src/processing_conformance_schema/fixtures/valid-render.json</files>
  <action>
Per Gap 1's root cause, confirmed by reading `CheckProcessValidity()` (`SuperGenius/SGProcessingManager/src/processingbase/ProcessingManager.cpp`, the `case DataType::TENSOR:` and `case DataType::BUFFER:`/`case DataType::FLOAT:` blocks) and the generated `DataType.hpp`/`Generators.hpp` enum maps:

In `valid-inference.json`: change the single `inputs[0].type` value from `tensor` to `float`. `DataType::FLOAT` (like `DataType::TENSOR`) requires a `dimensions` object with a `width` field, which this input is currently missing entirely — that is why `CheckProcessValidity()` currently logs "Tensor type missing width" and rejects it. Add a `dimensions` object to that same input entry with `width: 16`, `block_len: 16`, `chunk_stride: 16` (matches the model's `input_nodes[0].shape` of `[1, 16]`; mirror the exact shape used in `SuperGenius/test/src/processing_datatypes/float-processing-definition.json`'s `inputFloat` entry, just with these width/block_len/chunk_stride values). Leave `outputs[0].type` (`tensor`) and everything else unchanged — `CheckProcessValidity()` only iterates and validates `processing_.get_inputs()`, never `get_outputs()`.

In `valid-render.json`: the single pass currently uses `shader_pipeline`, `framebuffer`, and `vertex_buffers` — none of these keys exist on the real `Pass` schema (verified against `Pass.hpp`: the real fields are `render_shader`, `render_target`, and a singular `vertex_buffer`, plus a required `vertex_layout`). Replace the pass's render-specific keys exactly as follows, mirroring the confirmed-working precedent at `SuperGenius/test/src/processing_dispatch/render-pass-valid-definition.json`:
1. Delete the `shader_pipeline` key. Add a `render_shader` key whose value is an object with one key `stages`, an array of two stage objects. First: `stage`: `vertex`, `type`: `spirv` (not `glsl` — these fixtures reference precompiled `.spv` files), `source`: the same URI currently under `shader_pipeline.vertex.source_uri_param` (`file://processing_conformance_regression/fixtures/passthrough.vert.spv`) but under the key `source`, not `source_uri_param` — `ShaderStage`'s `from_json` reads `j.at("source")` and throws if that key is absent. `entry_point`: `main`. Second stage object: identical shape for `stage`: `fragment`, `source` pointing at `passthrough.frag.spv`.
2. Delete the `framebuffer` key. Add a `render_target` key: `color_format`: `RGBA8`, `depth_format`: `D32_SFLOAT`, `width`: 64, `height`: 64, `clear_color`: `[0.0, 0.0, 0.0, 1.0]`, `clear_depth`: `1.0`.
3. Delete the `vertex_buffers` array entirely — wrong field name AND wrong shape (`Pass.vertex_buffer` is a single object with only a `source` string, not an array with `binding`/`stride`). Add a `vertex_buffer` key: `{"source": "input:vertexData"}`. `CheckProcessValidity()` requires this string to start with the literal prefix `input:`.
4. Add a `vertex_layout` key: an array containing one object `{"name": "inPosition", "format": "FLOAT32", "offset": 0}`. `CheckProcessValidity()` requires this array to be present and non-empty for RENDER passes.

Also in `valid-render.json`, fix the `vertexData` input entry: it currently declares `type: buffer` with `format: FLOAT32` and no `dimensions`. `DataType::BUFFER` only accepts `format: INT8` (any other format is a hard rejection) and requires `dimensions.width`. Remove the `format` field entirely from this input (omitting `format` triggers only a logged warning defaulting to INT8, not a rejection) and add a `dimensions` object with just `width: 1` — this exact shape (`buffer` type, no `format`, `dimensions: {"width": 1}`) is the confirmed-working pattern already used by `renderInput` in `render-pass-valid-definition.json`.
  </action>
