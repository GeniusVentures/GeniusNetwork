4. `InvalidBadModelFormat` — INFERENCE pass with `model.format: "UNKNOWN"` → `ASSERT_FALSE`, error mentions "format"
5. `InvalidUnknownPassType` — pass with `type: "UNKNOWN_TYPE"` → `ASSERT_FALSE`, error names the unknown type (D-08(d) regression — verify error, not silent fallthrough)
6. `RenderMissingShader` — RENDER pass with no `shader_pipeline` → `ASSERT_FALSE`, error mentions "shader"
7. `RenderBadSpirvRef` — RENDER pass referencing nonexistent `.spv` file → `ASSERT_FALSE`, error mentions SPIR-V or shader file
8. `EmptyJobDefinition` — empty JSON `{}` → `ASSERT_FALSE`
9. `MissingPassesArray` — valid JSON but no `passes` key → `ASSERT_FALSE`
10. `MultiplePassesValid` — 2 valid passes (1 INFERENCE + 1 RENDER) → `ASSERT_TRUE`

JSON fixtures go in `fixtures/` subdirectory. Each fixture is minimal — only the fields needed to trigger the specific validation path. Render pass fixtures reference shader files by relative `file://` URI (patched to absolute by the fixture base class).

For `ValidRenderPass`, include a reference to an existing shader fixture (from `processing_dispatch/` or the new SPIR-V fixtures from Plan 09-01). For `RenderBadSpirvRef`, reference a nonexistent file.
