Per D-06, D-07(c): create `SuperGenius/test/src/processing_conformance_hashing/` with:

**CMakeLists.txt** — `addtest()` macro, link `nlohmann_json` + `ProcessingBase` + `SGArtifacts` + `sgprocmanagersha`. No POST_BUILD fixture copy needed — reuses fixtures from `processing_datatypes/` via relative paths.

**output_hashing_test.cpp** — inherits `ProcessorConformanceFixture`. Test suite `OutputHashingTest`.

Test cases (TEST-06):

1. `ContentHashDeterministic` — Run the same MNN processor (use existing `buffer-processing-definition.json` from `processing_datatypes/`) twice → verify both runs produce identical content hash in the ProcessOutput. Uses `ProcessingManager::Process()` with the Phase 08 return type (ProcessOutput, not raw hash vector). Fixture JSON is loaded from `../processing_datatypes/` relative path (patched by `PatchedJson()`).

2. `ContentHashChangesOnDifferentInput` — Run with two different inputs → verify hashes differ. Reuse existing `buffer_tiny.mnn` with two distinct `.raw` inputs.

3. `ArtifactMetadataPresent` — After Process(), verify each output artifact has: non-empty `resource_name`, non-empty `artifact_id`, matching `pass_id`, `output_binding` reference, `format` field, `dimensions` (if applicable), `byte_size > 0`, `media_type` string. Per ARTF-01, ARTF-02.

4. `ChunkHashesPresent` — Verify `chunk_hashes` vector is non-empty and each chunk hash has correct byte length (SHA-256 = 32 bytes). Per ARTF-03.

5. `ManifestFieldsPresent` — After Process(), verify `ExecutionManifest` contains: `execution_id`, `attempt_id`, `task_id`/`subtask_id` (if applicable), `pass_id`, `executor_identity` (SHA-256 string), `model_identity`/`shader_identity` (when applicable), `input_artifact_hashes`, `output_artifact_hashes`, `start_time`/`end_time` (start < end), `terminal_state`, `resource_usage_summary`. Per ARTF-04.

6. `ManifestDeterministicSerialization` — Run same job twice → serialize both manifests to bytes → verify byte-identical output. Per ARTF-05.

7. `PersistenceRoundTrip` — Process() → serialize manifest → deserialize → verify fields match original. Tests the serialization round-trip.

For fixtures: reuse existing `processing_datatypes/` models and definitions rather than creating new ones. The test .cpp references fixtures via `PatchedJson("../processing_datatypes/buffer-processing-definition.json")` — the fixture base class handles path resolution.

**Note on Phase 08 dependency:** The ProcessOutput, Artifact, ExecutionManifest types must exist (they are created in Phase 08). If Phase 08 is not yet complete, these tests will not compile. Use `#ifdef` guards or conditional compilation if needed, but prefer to assume Phase 08 types are available.

Test cases (TEST-09):

1. `ProcessingResultShapePreserved` — Run Process() with a known MNN fixture (reuse `buffer-processing-definition.json` from `processing_datatypes/`) → convert ProcessOutput to ProcessingResult via `ProcessingResult::FromProcessOutput()` → verify: `hash.size() > 0`, hash matches the content hash from ProcessOutput, `output_names` list matches artifact resource names, `byte_buffers` contains output data, `output_locations` is a valid string (may be empty). The shape expected by existing SuperGenius callers is preserved.

2. `EmptyErrorOnSuccess` — Successful Process() → ProcessingResult → verify error field is empty/null. Per ARTF-06: "empty error field on success."

3. `OutputLocationsStringBehavior` — Verify `output_locations` is a string (not a protobuf repeated field or array). Per v1.0 convention: SuperGenius uses newline-delimited output-location strings. The migration adapter must preserve this.

4. `RoundTripNoDataLoss` — Process() → ProcessOutput → ProcessingResult → extract fields → verify all key fields (hash, byte buffers, output names) are byte-identical to ProcessOutput originals. No data loss in conversion.

The test reuses fixtures from `processing_datatypes/` via relative paths (same pattern as Task 1).
