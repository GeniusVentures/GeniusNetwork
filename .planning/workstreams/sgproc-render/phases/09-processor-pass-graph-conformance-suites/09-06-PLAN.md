Per D-08: create `SuperGenius/test/src/processing_conformance_regression/` with:

**CMakeLists.txt** — `addtest()` macro, link `nlohmann_json` + `ProcessingBase` + `SGExecution`. POST_BUILD copies `fixtures/` directory (including SPIR-V binaries from Plan 09-01).

**regression_test.cpp** — Two test suites: `RegressionTest` (TEST-10) and `RenderConformanceTest` (TEST-04 render + TEST-05). Both inherit `ProcessorConformanceFixture`.

**RegressionTest cases (TEST-10):**

1. `BugA_IndexMismatchInPassInputIndexing` (per D-08a): Multi-pass job where 2 passes exist and the second pass's input bindings reference pass indices that shift after the first pass is inserted. Fixture: `regression-a-index-mismatch.json` — a 2-pass job (MNN inference passes with distinct models). Verify: `ProcessingManager::Create()` succeeds, input bindings resolve to correct pass indices (not shifted). Assert FIXED behavior — the indices match the intended passes.

2. `BugB_ModelOnlyAssumptionCrashInParseBlockSize` (per D-08b): A shader-only render pass with NO `model` field. Fixture: `regression-b-parseblocksize-model-only.json` — a valid render pass definition with `shader_pipeline` but no `model` key at all. Verify: `ProcessingManager::Create()` succeeds (no crash), `ParseBlockSize()` returns a valid result (not a crash or exception). Assert FIXED behavior — the function handles model-less passes.

3. `BugC_OutputBufferZeroProducesCorrectResult` (per D-08c): An edge case where the output tensor has zero elements, triggering a fallback path that previously produced incorrect results. Fixture: `regression-c-output-buffer-zero.json` — an MNN inference pass with a model that produces a zero-element output. Verify: `Process()` returns a valid (non-error) result, output hash is correct for zero-element tensor, no garbage data. Assert FIXED behavior — the fallback produces the correct (empty or zero-length) result.

4. `BugD_UnsupportedPassTypeProducesError` (per D-08d): A job definition referencing an unregistered `PassType` enum value. Fixture: `regression-d-unsupported-passtype.json` — a pass with `"type": "UNSUPPORTED_TYPE"` (a value not in the PassType enum). Verify: `ProcessingManager::Create()` returns an error (not silent success), error message contains the pass type name. Assert FIXED behavior — produces error instead of silent fallthrough.

Each regression fixture JSON is minimal — only the fields needed to trigger the specific bug path. Inline comments in the JSON explain which bug is being triggered.

**Regression fixture JSON design:**

- `regression-a-index-mismatch.json`: 2 passes, both INFERENCE, with input bindings referencing pass indices. Use tiny MNN models from `processing_datatypes/` (e.g., `buffer_tiny.mnn` and `float_model.mnn`).
- `regression-b-parseblocksize-model-only.json`: Single RENDER pass, `shader_pipeline` referencing `passthrough.vert.spv`/`passthrough.frag.spv`, NO `model` field. Vertex buffer with 3 vertices (a triangle).
- `regression-c-output-buffer-zero.json`: INFERENCE pass with a model that has zero-element output tensor. May need a custom tiny `.mnn` model or reuse an existing one where output dimensions can be configured to zero.
- `regression-d-unsupported-passtype.json`: Single pass with `"type": "UNSUPPORTED_TYPE"` and minimal valid fields.

  <action>
Per D-05, D-06, TEST-04, TEST-05: Add `RenderConformanceTest` suite to `regression_test.cpp`.

**SetUpTestSuite()**: Call `sgns::sgprocessing::HasUsableVulkanDevice()`. If false, `GTEST_SKIP() << "No Vulkan device available — DISCRETE_GPU/INTEGRATED_GPU not found, or MoltenVK not present"`. Per D-05: probe once, skip entire suite if no GPU. Per Pitfall 4 in RESEARCH.md: use `SetUpTestSuite()` (not `SetUp()`) so the probe runs once for the whole suite.

Test cases:

1. `RenderPassFullPipeline` — Create ProcessingManager with a valid render pass JSON referencing `passthrough.vert.spv` and `passthrough.frag.spv` (from Plan 09-01). Create `ExecutionContext` with no cancellation (normal execution). Call `Process()`. Verify: result has value, output artifacts exist, output hash matches expected (all-white framebuffer → deterministic hash). Verify chunk hashes are non-empty. Per D-06: "full pipeline — Process() with fixture → verify output hash → verify teardown."

2. `RenderPassOutputHashDeterministic` — Run the same render pass twice. Verify both runs produce identical output hash. Per D-07(c): "output hash is deterministic across repeat runs."

3. `RenderPassTeardownVerified` — After Process() completes (success path), verify `RunTeardown()` fired. If ProcessingManager exposes teardown state, assert it. Otherwise, run a second Process() immediately — if teardown didn't fire, Vulkan resources would be leaked and the second run would fail or produce corrupted output. Second run succeeding implies teardown worked. Per D-07(d).

4. `RenderPassShaderFixturesValid` — Verify the SPIR-V fixtures load correctly: create ProcessingManager, get the shader pipeline from processing data, verify shader stages are present and SPIR-V bytecode is non-empty. Sanity check before the full pipeline test.

5. `MoltenVkEquivalentPath` — Same as `RenderPassFullPipeline` but with explicit assertion that the Vulkan device is from MoltenVK (check `VK_PHYSICAL_DEVICE_PROPERTIES.deviceID` or vendor ID). On non-macOS, this test also passes because the native Vulkan path is equivalent. The key assertion is that the render result is identical regardless of the Vulkan implementation. Per TEST-05: "Native Vulkan and MoltenVK paths run equivalent render fixtures."

**Render pass JSON fixture:** Define inline or as a separate `fixtures/render-conformance.json`. References `passthrough.vert.spv` and `passthrough.frag.spv` by relative `file://` URI. Defines: a small framebuffer (e.g., 64×64 RGBA8), a vertex buffer with 3 vertices forming a triangle, and a render pass with the pass-through shader pipeline. Expected output: 64×64 pixels of all-white (RGBA 255,255,255,255).

**CMakeLists.txt update (if not already in Task 1):** POST_BUILD copies `fixtures/` including `.spv` binaries and render JSON. Link `ProcessingBase` (which includes RenderProcessor).
