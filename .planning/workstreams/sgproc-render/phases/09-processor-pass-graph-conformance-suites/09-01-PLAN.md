Each script generates a tiny deterministic ONNX model → converts to `.mnn` via `MNNConvert`, produces a `.raw` input file and a `.raw` reference output (PyTorch forward pass). For each type:
- **audio**: 1D convolution net with 256-sample input. Output: `audio_tiny.mnn`, `audio_input.raw`, `audio_output_pt.raw`.
- **image**: 2D convolution net with 32×32×3 input. Output: `image_tiny.mnn`, `image_input.raw`, `image_output_pt.raw`.
- **ml**: Small multi-layer perceptron with 64-dim input. Output: `ml_tiny.mnn`, `ml_input.raw`, `ml_output_pt.raw`.
- **string**: Character-level embeddings model (tiny, <100 params). Input: tokenized 16-char input as int32. Output: `string_tiny.mnn`, `string_input.raw`, `string_output_pt.raw`. This is NEW — the existing `bert-tiny.mnn` is ~16MB; this smaller model is better for CI speed. If the existing `bert-tiny.mnn` already works and time is constrained, the script can emit the existing model path as a fallback.
- **volume**: 3D convolution net with 16×16×16 input. Output: `volume_tiny.mnn`, `volume_input.raw`, `volume_output_pt.raw`.

Each script follows the CLI pattern: `--length`, `--out-dir`, `--onnx`, `--raw`, `--pt`, `--ref` arguments. Scripts print the `MNNConvert` command to run after ONNX export (since `MNNConvert` is a separate tool, not a Python library). Also emit a comment with the exact `MNNConvert` invocation for the executor to run.

Generate the `.raw` input/output and `.mnn` model files by running each script + `MNNConvert` in a terminal. Place all generated fixtures in `SuperGenius/test/src/processing_datatypes/`.

Per D-02: create trivial pass-through vertex+fragment shader pair for RenderProcessor conformance tests. Place sources in `SuperGenius/test/src/processing_conformance_regression/fixtures/` (shared by Plan 09-06's RenderProcessor tests).

Vertex shader (`passthrough.vert`): Takes `vec3 inPosition` at location 0, passes through `gl_Position = vec4(inPosition, 1.0)`. No uniforms, no textures. Minimal valid GLSL 450.

Fragment shader (`passthrough.frag`): Outputs solid white `vec4(1.0, 1.0, 1.0, 1.0)` at location 0. No uniforms, no textures. Trivially deterministic — every pixel is (255,255,255,255) in RGBA8.

Compile both to SPIR-V using `glslangValidator`: `glslangValidator -V passthrough.vert -o passthrough.vert.spv` and `glslangValidator -V passthrough.frag -o passthrough.frag.spv`. Then validate: `spirv-val passthrough.vert.spv` and `spirv-val passthrough.frag.spv`.

Create the fixtures directory: `SuperGenius/test/src/processing_conformance_regression/fixtures/`. Place all 4 files there (2 `.glsl` sources + 2 `.spv` binaries).

Expected output for the pass-through render: a framebuffer where every RGBA8 pixel is (255,255,255,255). The expected hash for this output is trivially computable — a framebuffer of all-0xFF bytes.
