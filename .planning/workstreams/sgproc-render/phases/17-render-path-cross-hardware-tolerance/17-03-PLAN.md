<objective>
Build the texturing technique's schema and wire-format data path -- structurally the same as `vertex_buffer`'s existing "input:"-prefix binding, deliberately NOT the render-irrelevant `DataType::TEXTURE2_D` MNN-chunking shape (RESEARCH.md's explicit warning) -- so a render pass can declare a raw RGBA8 image input. This plan is the "define contracts" half of texturing's Interface-First split (17-CONTEXT.md D-05: texturing is "genuinely new infrastructure," the largest of the three techniques); Wave 3's Plan 17-04 is the "implement against them" half (the actual Vulkan sampler/descriptor/upload work).

Purpose: closes the schema/validation/wire-format portion of RENDTOL-01's texturing infrastructure gap, and -- critically -- closes RESEARCH.md Pitfall 2 (wire-format pairing) by editing `SerializeRenderPassConfig`/`ParseRenderPassConfig` together in one task, never split across plans/waves.
Output: `texture_buffer`/`texture_filter` schema definitions + regenerated headers, `CheckProcessValidity`'s new fail-closed gate, `Process()`'s new texture-fetch block, both wire-format functions' new trailing texture section, the synthetic RGBA8 source image asset, and an automated `Create()`-only GTest proving the prefix gate (accept `input:`, reject `output:`) without depending on Wave 3's not-yet-built sampler code.
</objective>
