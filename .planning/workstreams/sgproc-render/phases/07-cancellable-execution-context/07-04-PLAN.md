Since Vulkan doesn't expose easy per-process allocation counters without VMA or validation layers, use these leak detection strategies (document which is used):

1. **Vulkan object leak detection (preferred):** If Vulkan Validation Layers are enabled (ENABLE_VULKAN_VALIDATION), the layers track object creation/destruction. Run tests with validation layers enabled in debug builds.

2. **Process memory tracking (fallback):** Track process RSS before/after N iterations using platform APIs (`GetProcessMemoryInfo` on Windows, `/proc/self/statm` on Linux). Assert RSS doesn't grow beyond a threshold (e.g., 10% growth over 10 iterations).

3. **MNN session count tracking (custom):** Add a debug-only `static std::atomic<int> s_activeMnnSessions` counter that increments on `createSession` and decrements on `releaseSession`. Assert counter returns to initial value after each iteration.
