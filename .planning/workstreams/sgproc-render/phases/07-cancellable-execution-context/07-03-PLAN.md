**C) Teardown stack adoption (per D-14):**

After creating the MNN interpreter (`std::shared_ptr<MNN::Interpreter> net(...)`) under `VulkanInitMutex`, register cleanup:
```cpp
{
    std::lock_guard<std::mutex> lock(VulkanInitMutex());
    net = std::shared_ptr<MNN::Interpreter>(MNN::Interpreter::createFromBuffer(modelFile_bytes.data(), modelFile_bytes.size()));
    if (!net) {
        return ProcessingResult{};
    }
    
    // Register teardown: MNN session cleanup
    // Capture net by value (shared_ptr copy) to keep it alive until teardown fires
    PushTeardown([net]() {
        // net's destructor handles interpreter cleanup when shared_ptr refcount reaches zero
        // No explicit destroy needed — MNN::Interpreter destructor is sufficient
    });
    
    MNN::ScheduleConfig config;
    // ... existing config setup ...
    auto session = net->createSession(config);
    if (!session) {
        RunTeardown(); // clean up the interpreter registered above
        return ProcessingResult{};
    }
    
    // Register teardown for the session
    PushTeardown([net, session]() {
        net->releaseSession(session);
    });
}
```

The teardown stack handles three cases:
1. **Normal completion:** RunTeardown() not explicitly called — let ProcessingManager's catch block or post-execution cleanup handle it. Actually, for normal success, RunTeardown() should be called at the end of StartProcessing() for MNN processors (unlike RenderProcessor which creates persistent Vulkan resources). Add `RunTeardown()` at the end of the success return path in each MNN processor.

2. **Cancellation:** RunTeardown() called before returning CANCELLED ProcessingResult.

3. **Exception:** ProcessingManager's catch block calls RunTeardown() (07-02).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ExecutionContext → Processor | All field values (cancel token, budgets, callbacks) cross trust boundary into processor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 | Denial of Service | CancellationToken::IsCancelled() in tight loop | mitigate | Cancel checks at coarse stage boundaries only (D-04, max 4 per processor). Not checked per-API-call — zero per-call overhead. |
| T-07-10 | Tampering | maxOutputArtifactBytes from untrusted schema | mitigate | Budget check at processor level is belt-and-suspenders — CapabilityValidator pre-checks (D-07) are the primary gate. Processor check catches any validator bypass. |
| T-07-11 | Denial of Service | MNN session leak on cancel | mitigate | PushTeardown registers session cleanup at creation time. RunTeardown() on cancel ensures session released. |
| T-07-12 | Elevation of Privilege | Teardown function captures shared_ptr by value | mitigate | Teardown lambdas capture shared_ptr copies — MNN::Interpreter stays alive until teardown fires. No dangling references. |
</threat_model>
