<objective>
Close the CMake transitive-dependency gap Phase 1 left open: `SGProcessingManager`'s exported `SGProcessors` target PUBLIC-links `vk-bootstrap::vk-bootstrap`, but only `SGProcessingManager`'s own `CommonBuildParameters.cmake` calls `find_package(vk-bootstrap CONFIG REQUIRED)`. `GeniusSDK` and `GeniusWallet` both consume `SGProcessingManager` via `find_package(SGProcessingManager CONFIG REQUIRED)` without independently resolving this transitive dependency, so any CMake configure of either project against a submodule pointer including Phase 1's changes fails with a "target vk-bootstrap::vk-bootstrap not found" error. Per CMAKE-01, mirror the existing per-consumer `find_package` convention (not `find_dependency()` propagation) into both files.

Purpose: Unblock CMake configure for GeniusSDK and GeniusWallet against any SGProcessingManager submodule pointer that includes Phase 1's vk-bootstrap vendoring.
Output: Two mechanically-identical `find_package(vk-bootstrap CONFIG REQUIRED)` blocks, one in each consumer's `CommonBuildParameters.cmake`, using the file's own established `THIRDPARTY_BUILD_DIR` variable convention.
</objective>
