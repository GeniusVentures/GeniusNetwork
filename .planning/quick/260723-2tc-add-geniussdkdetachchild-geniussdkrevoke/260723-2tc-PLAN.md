<objective>
Add 3 new public GeniusSDK C API functions -- `GeniusSDKDetachChild`, `GeniusSDKReplaceMain`, `GeniusSDKRevokeChild` -- that let external callers trigger the child-wallet lifecycle transitions Phase 5 already implemented at the `GeniusNode`/`TransactionManager` level (child-initiated Detach/Replace-Main, main-initiated Revoke), without linking SuperGenius directly. All 3 reuse the existing `GeniusNodeReturnValue_t` enum -- no new value is introduced.

Purpose: Phase 5 (child-wallet-lifecycle-states) shipped `GeniusNode::DetachChild`, `GeniusNode::ReplaceMain`, and `GeniusNode::RevokeChild` plus the full consensus-side enforcement (`CheckParentChildAuthority` revoke branch, `FilterRegistration` gate 3b's `supersedes_sequence` check), but stopped at the SuperGenius layer -- STATE.md flags this gap explicitly. This quick task is a pure C-API exposure layer, adding zero new business logic to SuperGenius, mirroring Phase 2's (`GeniusSDKRegisterChild`) and Phase 4's (`GeniusSDKFundChild`/`GeniusSDKRecoverFromChild`) exact wrapper pattern.
Output: `GeniusSDK.h`/`GeniusSDK.cpp` gain 3 new thin wrapper functions, each following an exact existing analog -- `GeniusSDKRegisterChild` for the metadata-struct-conversion + no-address-null-check idiom (Detach), and `GeniusSDKRecoverFromChild` for the `const char*` address null/empty-check + fire-and-forget idiom (ReplaceMain's address arg, Revoke).
</objective>
