# Quick Task 260817-m23: Update GeniusSDK CommonBuildParameters.cmake Summary

**Fixed Vulkan_INCLUDE_DIR-NOTFOUND on Windows by porting SuperGenius's proven vendored-Vulkan-Headers discovery pattern into GeniusSDK/cmake/CommonBuildParameters.cmake; a downstream shaderc::shaderc gap surfaced next and was fixed the same way, and GeniusSDK now configures and builds cleanly in Release x64**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-08-17
- **Tasks:** 2 completed, plus one same-session follow-up fix (shaderc::shaderc gap) to reach a fully working build
- **Files modified:** 1 (GeniusSDK/cmake/CommonBuildParameters.cmake, across two commits)

## Accomplishments

- Replaced the non-Apple Vulkan discovery block in `GeniusSDK/cmake/CommonBuildParameters.cmake` (previously just `find_package(Vulkan)` / `if(NOT TARGET Vulkan::Vulkan)` with no `Vulkan_INCLUDE_DIR` fallback, causing `Vulkan_INCLUDE_DIR-NOTFOUND` on Windows) with SuperGenius's working pattern:
  - Added `set(VulkanHeaders_DIR "${THIRDPARTY_BUILD_DIR}/Vulkan-Headers/share/cmake/VulkanHeaders" CACHE PATH ...)` + `find_package(VulkanHeaders CONFIG REQUIRED)` before the existing `find_package(Vulkan)` call
  - Added `set(Vulkan_INCLUDE_DIR "${THIRDPARTY_BUILD_DIR}/Vulkan-Headers/include")` as the first line inside the existing `if(NOT TARGET Vulkan::Vulkan)` block, keeping the existing `VULKAN_SDK` env-var fallback and `find_package(Vulkan REQUIRED)` unchanged
  - Added an unconditional `set_target_properties(Vulkan::Vulkan PROPERTIES INTERFACE_INCLUDE_DIRECTORIES "${THIRDPARTY_BUILD_DIR}/Vulkan-Headers/include")` override after the if-block, with an original-wording comment explaining it forces the vendored v1.4 headers to avoid version-mismatch errors with `vk-bootstrap`
- Left the APPLE/moltenvk block (lines 10-20) and the existing `vk-bootstrap` `find_package` block completely untouched, as instructed
- Committed the change inside the `GeniusSDK` submodule's own git repository (branch `dev_childwallet`), not the outer super-repo
- Ran a real `cmake .. -G "Visual Studio 17 2022" -A x64 -DCMAKE_BUILD_TYPE=Release` configure from `GeniusSDK/build/Windows/Release` against the real absolute path (stale pre-fix `CMakeCache.txt` present, as expected per the plan) - confirmed the original `Vulkan_INCLUDE_DIR-NOTFOUND` bug no longer occurs; the log shows `Found Vulkan: W:/gnus/GeniusNetwork/thirdparty/build/Windows/Release/Vulkan-Loader/lib/vulkan-1.lib (found version "1.4.357")`
- Configure then failed on a separate, unrelated downstream CMake error (see Issues Encountered) - re-ran configure a second time to confirm the failure is deterministic (identical error, exit code 1 both times) before reporting
- Did not attempt `cmake --build` (step 2) since the plan gates it on step 1 succeeding, which it did not

## Issues Encountered

**Downstream CMake error unrelated to the Vulkan fix, surfaced after Vulkan resolved successfully:**

The first `find_package(Vulkan)` call (before the fix's fallback branch runs) still logs `Could NOT find Vulkan (missing: Vulkan_INCLUDE_DIR) (found version "")` - this is expected and matches SuperGenius's own log output, since that first attempt runs before `Vulkan_INCLUDE_DIR` is set. The fix's fallback branch (`if(NOT TARGET Vulkan::Vulkan)`) then runs and succeeds:

```
-- Could NOT find Vulkan (missing: Vulkan_INCLUDE_DIR) (found version "")
-- Found Vulkan: W:/gnus/GeniusNetwork/thirdparty/build/Windows/Release/Vulkan-Loader/lib/vulkan-1.lib (found version "1.4.357")  missing components: glslc glslangValidator
```

Configure then proceeds through ZLIB, GTest, fmt, MNN, vk-bootstrap, protobuf, OpenSSL, Boost, RapidJSON, nlohmann_json, and reaches the SuperGenius/GeniusSDK integration `find_package` calls, where it fails verbatim as follows (identical on two separate runs, exit code 1 both times):

```
-- Configuring done (2.3s)
CMake Error at W:/gnus/GeniusNetwork/SuperGenius/build/Windows/Release/SuperGenius/lib/cmake/SGProcessingManager/SGProcessingManagerTargets.cmake:125 (set_target_properties):
  The link interface of target "SGShaderCompiler" contains:

    shaderc::shaderc

  but the target was not found.  Possible reasons include:

    * There is a typo in the target name.
    * A find_package call is missing for an IMPORTED target.
    * An ALIAS target is missing.

Call Stack (most recent call first):
  W:/gnus/GeniusNetwork/SuperGenius/build/Windows/Release/SuperGenius/lib/cmake/SGProcessingManager/SGProcessingManagerConfig.cmake:10 (include)
  W:/gnus/GeniusNetwork/GeniusSDK/cmake/CommonBuildParameters.cmake:448 (find_package)
  W:/gnus/GeniusNetwork/GeniusSDK/build/CommonBuildParameters.cmake:5 (include)
  CMakeLists.txt:20 (include)


-- Generating done (0.7s)
CMake Generate step failed.  Build files cannot be regenerated correctly.
```

This was a pre-existing, previously-undiscovered gap: SuperGenius's own exported `SGProcessingManagerTargets.cmake` (an installed/generated CMake export file, not something Task 1 touched) declares `SGShaderCompiler`'s link interface as including `shaderc::shaderc`, but nothing in the build chain (neither `GeniusSDK/cmake/CommonBuildParameters.cmake` nor `SuperGenius/build/CommonBuildParameters.cmake` as included transitively) called `find_package(shaderc ...)` to define that imported target when consumed from `GeniusSDK`'s configure. The Task 1 plan's assumption that "nothing in GeniusSDK references shaderc" held for the file's own direct contents, but not transitively via the exported `SGProcessingManager` target it `find_package()`s.

**Resolution (orchestrator follow-up, commit `181d1e2`):** ported the same hand-rolled `if(NOT TARGET shaderc::shaderc) add_library(shaderc::shaderc STATIC IMPORTED GLOBAL) ... endif()` block from `SuperGenius/build/CommonBuildParameters.cmake` into `GeniusSDK/cmake/CommonBuildParameters.cmake`, placed immediately before the `evmrelay`/`ProofSystem`/`SGProcessingManager`/`SuperGenius` `find_package()` calls, using `THIRDPARTY_BUILD_DIR` (no underscore) for consistency with the rest of the file. Verified `thirdparty/build/Windows/Release/shaderc/lib/shaderc_combined.lib` and the matching include dir exist before wiring it up.

Re-ran `cmake .. -G "Visual Studio 17 2022" -A x64 -DCMAKE_BUILD_TYPE=Release` — configure completed clean (`Configuring done` / `Generating done`, no errors). Then ran `cmake --build . --parallel 8 --config Release` — completed with **exit code 0**: `GeniusSDK.lib`, `GeniusSDK_shared.dll`, `SDKExample.exe`, `SDKIdleExample.exe`, and `GeniusSDKService.exe` all built successfully.
