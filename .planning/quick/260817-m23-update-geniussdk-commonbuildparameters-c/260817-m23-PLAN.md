<objective>
Fix Vulkan discovery in `GeniusSDK/cmake/CommonBuildParameters.cmake` so it locates the vendored `Vulkan-Headers` include directory on non-Apple platforms (currently `Vulkan_INCLUDE_DIR` resolves to `NOTFOUND` on Windows), matching the working pattern already proven in `SuperGenius/build/CommonBuildParameters.cmake`. Then configure and build the `GeniusSDK` CMake project in Release x64 with Visual Studio 17 2022 to confirm the fix resolves the actual build.

Purpose: A prior CMake configure attempt for GeniusSDK on Windows failed with `Vulkan_INCLUDE_DIR-NOTFOUND` because the file's non-Apple branch calls `find_package(Vulkan REQUIRED)` without ever pointing CMake at the vendored `Vulkan-Headers/include` dir (only the Apple/moltenvk branch sets `Vulkan_INCLUDE_DIR` explicitly). SuperGenius's own `CommonBuildParameters.cmake` already solves this for all platforms via an explicit `VulkanHeaders` config package lookup plus a manual `Vulkan_INCLUDE_DIR` fallback and an `INTERFACE_INCLUDE_DIRECTORIES` override forcing the vendored headers even when a system Vulkan SDK is found (avoiding version-mismatch errors against `vk-bootstrap`, which was built against the vendored v1.4 headers).
Output: `GeniusSDK/cmake/CommonBuildParameters.cmake` updated and committed inside the `GeniusSDK` submodule; a successful (or precisely diagnosed) CMake configure + build of the `GeniusSDK` target in `GeniusSDK/build/Windows/Release`.
</objective>
