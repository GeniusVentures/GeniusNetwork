<objective>
Add the two shared primitives that every later plan in this phase builds on: a certified-parent CRDT lookup on `Blockchain` (D-63), and a parameterized signature-verification helper on `GeniusTransaction` (needed to implement D-60's "main's signature is accepted for a certified child's transaction" mechanism).

Purpose: `CheckCertifiedParent` is the single shared "is this child certified, and who is its main" lookup that Plan 02's gate, Plan 02's `CheckTransactionAuthorization` extension, and Plan 02's `GeniusInputValidator.cpp` extension all call — it must live on `Blockchain` because `Blockchain` (not `TransactionManager`) is the dependency already passed into `GeniusInputValidator::ValidateWitness`. `CheckSignatureAgainst` is the minimal, behavior-preserving refactor that lets `CheckTransactionAuthorization` (Plan 02) verify a transaction's signature against the certified main's address instead of only the transaction's own declared source address.
Output: Two new, independently testable primitives with zero behavior change to any existing caller.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CRDT-stored `reg/{addr}` blob → `Blockchain::CheckCertifiedParent` | Untrusted/attacker-writable CRDT data crosses into a trusted lookup used by consensus gates |
| Arbitrary address argument → `GeniusTransaction::CheckSignatureAgainst` | Generic verification primitive; safety depends entirely on what address callers pass in (scoped by Plan 02, not this plan) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | `CheckCertifiedParent` | high | mitigate | Uncertified/malformed `reg/` entries return `std::nullopt` via the `CheckCertificate(reg_hash)` gate (D-26) — a registration that hasn't reached consensus certification never yields a usable main address |
| T-03-02 | Tampering | `CheckCertifiedParent`'s `ParseFromArray` | medium | mitigate | Parse failure (malformed bytes at the `reg/` key) returns `std::nullopt`, not a crash or garbage value — matches the existing `TransferTransaction`/`RegistrationTransaction` deserializer failure convention |
| T-03-03 | Elevation of Privilege | `CheckSignatureAgainst` reused with an attacker-influenced address | low | accept | This plan only adds the primitive; it has no caller yet. Plan 02 is the only consumer and gates every call behind `CheckCertifiedParent`'s certified lookup — exposure is scoped there, not here |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No new package-manager dependencies in this plan — pure C++ within the existing SuperGenius codebase |
</threat_model>
