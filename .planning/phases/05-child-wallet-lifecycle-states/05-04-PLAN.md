<objective>
Prove, with automated tests extending the existing `RegistrationTransactionE2ETest` fixture (D-65 — no new test file), that Detach and Replace-Main work end-to-end through the real `FilterRegistration` CRDT gate, that gate 3b correctly detects forks and rejects orphaned lifecycle-change transactions, and that Detach preserves the child's standalone-capable invariants (LIFE-04).

Purpose: Plans 01-03 built the mechanism; this plan is where CONTEXT.md's "Full Adversarial Coverage" requirement (D-73) is actually discharged for the child-signed (Detach/Replace-Main) half of the lifecycle surface — fork detection and re-registration are the two adversarial/continuity properties the design doc calls out by name (§9.3-9.4, §10).
Output: Six new passing GTest cases in the existing `RegistrationTransactionE2ETest` fixture, using `account_`/`tm_` as the self-registering/self-detaching child — mirroring the existing `ChildRegistrationEndToEnd`/`RegisterChildAutoDeriveFirstRegistration` tests' role assignment (NOT the CONS-02/REGR-family tests' main-vs-`child_account_` role assignment, since Detach/Replace-Main are child-initiated).
</objective>
