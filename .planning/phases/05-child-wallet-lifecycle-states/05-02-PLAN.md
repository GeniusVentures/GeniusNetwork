<objective>
Wire the new "revoke" transaction type into every dispatch point `TransactionManager` uses to recognize, apply, and gate transaction types, and add the `FilterRegistration` fork-prevention gate that protects Detach/Replace-Main.

Purpose: Phase 3 discovered that a missing `transaction_parsers` entry silently blocks an entire tx type from ever certifying ("Unknown tx type", `TransactionManager.cpp:4224-4228`) — this plan closes that exact class of gap for `"revoke"` from day one (dispatch table, `DeSerializeEmbeddedTransaction` switch, and a real `ParseRevokeTransaction` that actually flips `detach_flag` on the target `reg/{child_addr}` record). It also adds the `supersedes_sequence` CRDT-filter gate (D-38) that is the single fork-prevention mechanism shared by Detach and Replace-Main, and the `CheckParentChildAuthority` "revoke" branch (main-signature-already-verified authority check) that is Revoke's dedicated validation path (design doc §8.1).
Output: "revoke" transactions certify, apply their effect to the target reg/ record, and are rejected when unauthorized or targeting the wrong sequence. Detach/Replace-Main-style lifecycle-change RegistrationTx entries are rejected on fork.
</objective>
