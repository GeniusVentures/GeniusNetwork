<objective>
Add the proto schema and C++ transaction-class primitives every later plan in this phase builds on: `detach_flag`/`supersedes_sequence` on `RegistrationTx` (Detach and Replace-Main both reuse these two fields), a new first-class `RevokeTx` message plus `EmbeddedTransaction` oneof arm 9, and a new `RevokeTransaction` C++ class mirroring `RegistrationTransaction`. `detach_flag` is the concrete field that encodes D-34's four-state lifecycle model (Unregistered/Registered/Detached/Revoked derived purely from `reg/{child_addr}`'s own fields — no separate state-machine engine).

Purpose: per the v1.0 lifecycle design (`docs/03-02-reward-policy-lifecycle.md` §7-9, §11 Proto Evolution Summary), Detach and Replace-Main are both just `RegistrationTx` variants distinguished by `detach_flag`/`main_address`, while Revoke is a dedicated main-signed transaction type (§8.1: "keeps authority actions separate from value transfers... avoids overloading the transfer type with lifecycle semantics"). This plan produces both artifact families so Plan 02 (consensus/CRDT wiring) and Plan 03 (caller-facing methods) have real types to work with.
Output: Updated `.proto` schemas, an extended `RegistrationTransaction`, and a new `RevokeTransaction` class — all additive, zero behavior change to any existing caller.
</objective>
