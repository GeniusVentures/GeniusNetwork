<objective>
Add the child-initiated `DetachChild`/`ReplaceMain` and main-initiated `RevokeChild` caller-facing methods, at both the `TransactionManager` and `GeniusNode` layers, using the exact two-layer convention already established by `RegisterChild`/`RecoverFromChild`.

Purpose: Plans 01-02 built the transaction types and consensus/CRDT wiring; this plan is what actually lets a child (or main) TRIGGER a Detach, Replace-Main, or Revoke. Per CONTEXT.md's locked decision (D-71), these are dedicated, discoverable, symmetric methods — not overloads of `RegisterChild`/`TransferFunds` — matching the project's established D-62/D-66 precedent. No GeniusSDK C API wrappers are added in this phase (D-72) — SDK exposure of Detach/Revoke/Replace-Main is deferred to a future phase, mirroring the Phase 3→4 split.
Output: Six new public methods on `TransactionManager` (`DetachChild` x2, `ReplaceMain` x2, `RevokeChild` x1) and their `GeniusNode` wrappers (`DetachChild` x2, `ReplaceMain` x2, `RevokeChild` x2 incl. a `WaitForFinalized` timeout overload).
</objective>
