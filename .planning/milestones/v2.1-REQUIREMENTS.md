# Requirements: GNUS Child Wallet

**Defined:** 2026-07-17
**Core Value:** Main wallet must be able to discover, monitor, and manage registered child wallets through consensus-visible state

## v2.1 Requirements

Requirements for milestone v2.1: Main Wallet Child Balance Query.

### Balance Query

- [x] **BALT-01**: Main wallet can query a registered child wallet's child token balance by child address and token ID, computed from locally-synced CRDT UTXOs via the existing `UTXOManager::GetBalance(token_id, address)` pattern

### Integration

- [x] **INTG-01**: Multi-node integration test validates end-to-end: child node registers with main node, child receives child token funds, main node queries child balance via `GetChildBalance`, result matches the expected funded amount

## Future Requirements

Deferred to future milestones.

### Monitoring Dashboard

- **MON-01**: Main wallet displays per-child balance, all assets/tokens, activity history, and escrow status (DISC-02)
- **MON-02**: Main wallet monitors child activity and lifecycle status derived from registration record

### API Layer

- **API-01**: gRPC endpoint exposes child balance query to external callers
- **API-02**: GeniusSDK method wraps child balance query for game/app developers

### Multi-Token

- **TOK-01**: Main wallet queries child balance across all token types (GNUS, child tokens, NFTs)

## Out of Scope

| Feature | Reason |
|---------|--------|
| gRPC balance endpoint | Internal node capability only; API layer deferred to future milestone |
| GeniusSDK child balance method | SDK integration deferred; node-level capability first |
| Full monitoring dashboard (DISC-02) | This milestone focuses on balance only; monitoring deferred |
| Multi-token balance | Child token only for v2.1; all-tokens query deferred |
| Balance display formatting | FormatTokens/ConvertToChildToken deferred to API phase |
| Direct child query (request/response) | Balance computed from synced CRDT only; no live query to child node |
